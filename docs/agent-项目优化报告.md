## 三、架构定案：四层无重叠

| 层 | 职责 | 边界 |
| --- | --- | --- |
| Skill | 知识注入 | 只进提示词，不执行 |
| MCP | 外部工具通道 | 跨进程 / 网络 |
| 插件 | 宿主扩展 | 进程内，改界面、加能力、热插拔 |
| 沙箱 | 执行隔离 | 只跑 agent 自产代码 |

### 关键澄清

1. **插件与扩展二合一（2026-09-19 定案，取代本条原「归位」说）**：扩展与插件统一为「插件」——一个目录 + 一份 manifest.json，清单只声明「有什么」（面板 / 工具 / 权限），**不分界面型 / 能力型**（原分支作废：board 名义界面型实有三项写能力，分类名不副实）。对外只留四个词：**Skill / MCP / 插件 / 沙箱**；「扩展」一词退役。MCP 不并入——MCP 是公开标准协议，兼容责任在外；WASM 降为插件工具的可选实现 / 沙箱轻量档。已落地：P18 施工单 027（`docs/plugin-contract-v1.md`）。
2. **模型自主生成**：插件清单 `source` 字段取三值 `built_in` / `user` / `model_generated`（原四值枚举含 mcp/wasm 作废——MCP 是一层不是一种来源，WASM 是一种实现不是一种来源）。模型自产插件走 draft 隔离区（内存态、权限一律清空），一键转正后持久化。已落地（P18）；v1 生命周期为「到重启」，会话级隔离待 P22 有真实生产者时补。
3. **WASM 与插件解耦**：WASM 不作为插件载体，改任"沙箱后端之一"（详见第五章）。

## 五、沙箱方案（WASM 退出主位）

### 决策背景

WASM 只吃预编译模块，装不下模型现场写的 shell / python；而"自动模式下执行本地命令、产出新文件"恰好是核心场景。因此 WASM 不适合作为 agent 沙箱主位。

**与 Tabbit 桌面端任务模式的等价性**：读写文件、跑命令、产出新文件全部可以做到，因为走的是 OS 原语而非 WASM，任意 shell / python 都能跑。唯一差别是产物落盘方式——桌面端直接写关联文件夹；沙箱方案先落临时工作区，过一遍 diff 再提交到授权目录。体验一致，沙箱只是给真实文件多加了道审批。

### 接口设计（先冻结，后端可替换）

```rust
trait Sandbox {
    fn run(&self, cmd: &Command, policy: &Policy) -> Result<Output>;
}

struct Policy {
    writable: Vec<PathBuf>,   // 可写目录白名单
    network: NetworkPolicy,   // Off / ProxyWhitelist / On
    timeout: Duration,
    max_output: usize,
}
```

### 三档后端

| 档位 | 实现 | 用途 |
| --- | --- | --- |
| 默认 | Linux `bwrap` + Landlock + seccomp；macOS Seatbelt；Windows Restricted Token + Job Object + ACL | 任意 shell / python |
| 可选 | microVM（libkrun 或 Firecracker），特性开关 | 浏览器会话、不可信三方代码 |
| 轻量 | WASM（现有 403 行） | JS、纯计算、插件检疫 |

### 外部依据

- 最主流的两个本地 coding agent（Claude Code、Codex CLI）均不使用 Docker 或 VM，直接使用内核原语：Linux 走 bubblewrap，macOS 走 Seatbelt。
- Rust 侧可接现成 crate `ai-sandbox`（已封装 Linux bwrap+seccomp+Landlock、macOS Seatbelt、Windows Restricted Token）。
- 若要更强隔离可看 microsandbox（libkrun，启动 <200ms，Apache-2.0，自带 MCP 集成）。

### Windows 策略：不强制装 WSL2

- Windows 原生方案存在：Restricted Token + Job Object + ACL（`ai-sandbox`、agentbox 等已实现）。
- 缺失 seccomp 级 syscall 过滤与网络命名空间，防护低一档；但能拦住"agent 误删工作区外文件"这一主要事故形态。
- **四档探测链**：启动依次探测 WSL2 → 原生受限令牌 → 确认模式，有则升档、无则降级为逐步确认。
- UI 明示当前档位（Native / WSL2 / Restricted / 确认模式）。

### 产物落地

执行在隔离区，产出先落临时工作目录，经 diff 后再提交到目标路径。**执行隔离与结果入库分两道闸门**。

## 六、插件体系：热插拔与兼容策略

### 6.1 热插拔的真正卡点

技术上不卡，卡在"开源即合同"——插件 API 一旦公开就需长期兼容，改一次所有插件作废。四个具体卡点：

- **扩展点定几个**：先只放工具注册 + 面板注册两个并冻结，其余后续只增不改。
- **unload 谁来回收**：插件注册过工具、面板、定时器、事件回调，靠插件自觉必然泄漏；靠宿主反向记账需先设计注册追踪。
- **运行中禁用怎么办**：正在跑的任务是杀、等完还是挂起，需三选一。
- **版本与状态迁移**：内核升级后老插件如何退场、旧状态是否迁移。

前端侧更麻烦：Svelte 组件是编译期结构，动态加载面板需先做运行时组件加载器。

### 6.2 版本更新会不会弄坏用户插件

分三档：

| 变更类型 | 后果 |
| --- | --- |
| 只改内核实现（拆 server.rs、换沙箱后端） | 插件无感，绝大多数更新属此类 |
| 改契约签名（工具注册函数加参、删字段） | 老插件加载直接报错，用户看到"插件坏了" |
| 改语义不改签名（生命周期触发时机变化） | 最危险：不报错但行为诡异，难复现 |

### 6.3 省事方案：不自造插件 API，把兼容责任外包

**契约只剩一个 manifest schema。** 插件 = 目录 + `manifest.json`，声明工具、面板、所需权限。解析器**忽略未知字段**，只要坚持"只增不删"，加字段天然向后兼容。

**能力全走现成协议。** 工具用 MCP 进程暴露，面板用 iframe + postMessage。MCP 是公开规范，postMessage 是浏览器标准，**版本兼容不归自己管**。manifest 里只写"注册了一个 MCP server / 一个面板 URL"。

**生命周期交给运行时。** 进程杀了即卸载，iframe 移除了即卸载，不自造 `unload`。唯一要写的是资源域：每插件一个域，域内注册的东西（工具、面板、定时器）统一记账，销毁时整域清空。

**版本策略偷懒**：`apiVersion` 一个常量，不匹配就拒绝加载并提示升级，**不做 shim**。README 写清 v0.x 期间不保证兼容。

**唯一要写对的两件事**：manifest 校验、资源域回收。

### 6.4 借鉴 dsh（Cordis）的教训

dsh 是同类 agent，其插件架构基于 Cordis（Koishi 内核）。Cordis 的设计哲学极其克制——只做三件事：**生命周期管理、依赖解析、上下文传播**，其余（路由、命令、存储、权限）全交给插件。

**dsh 的四个典型症状与病根**

| 症状 | Cordis 管不管 | 真实原因 |
| --- | --- | --- |
| 版本更新就坏 | 不管 | 做 DI 解析，不做契约版本；服务名是稳定键位，实现换签名无人拦 |
| 插件互相冲突 | 半管 | `ctx.xxx` 是全局唯一键，两个插件提供同名服务天然撞车 |
| 和 agent 自身冲突 | 不管 | 没有保留区概念，内置服务名与插件服务名同一张表 |
| 历史会话加载失败 | **不管** | 见下 |

**病根**：Cordis 的招牌能力"可逆副作用"能撤销的只是**内存里的东西**。一旦数据写入数据库、会话记录里存了"这段用某插件渲染"，插件消失后该记录即成孤儿。Cordis 对此没有管辖权。

**为什么 dsh 不那样做**：不是不想，是框架边界决定。极薄内核把复杂度锁在插件层，同时把持久化兼容与契约版本的责任转嫁给了应用层。dsh 享受了"换插件即改产品行为"的自由，代价就是无人强制补上持久化层和契约版本——**自由与脆弱是同一设计选择的两面**。

**结论**：dsh 那四个毛病是同一个病——**插件能改到内核存下来的东西**。解法一条纪律：插件只能碰"今天随便重建的"，碰不到"昨天存下来的"。

### 6.5 本项目的优势：从"约定"升级为"物理隔离"

为什么本项目能做而 dsh 容易出问题，差别在**写盘口在谁手里**：

1. **Cordis 是库，不是应用**：只管内存可逆副作用，不管数据库。
2. **本项目写入点（勘误 2026-09-19）**：本报告原称「写入点收敛，所有落盘走同一入口」——**与代码不符**，实际落盘散在 8+ 处（会话 / settings 7 个调用点 / 事件流水 / 记忆 / 影子仓库 / 技能 / 附件内联等）。P18（施工单 027）已新增统一存储入口 `src/storage.rs`（原子写 + 审计），先收会话与 settings 两大高频点，插件侧只有命名空间内的结构化读写——物理隔离由此补齐。
3. **生态尚未开放**：现在无人拿得到存储句柄，自然无人绕得过。

**关键警示**：此优势来自"还没被绕过"，不是"绕不过"。等第三方插件进来，只要它拿到 raw 存储句柄，照样塌。因此 P18 必须**把存储 API 收窄成只读 + 结构化写入，插件永远碰不到底层句柄**。（已落地：P18 存储一门 + 插件命名空间 API，见 `src/storage.rs`。）

### 6.6 五条落地纪律

- **契约带版本**：`apiVersion` + 加载时校验 + 弃用先告警再删。
- **命名空间隔离**：每插件自动加前缀；内核命名为保留区，插件禁止写入。
- **会话数据只存纯数据**：不存插件引用。渲染时插件不在，降级为纯文本占位，**绝不报错**。
- **崩溃隔离**：面板跑 iframe、工具跑独立进程，插件崩溃不影响 agent。
- **资源域回收**：每插件一个可逆副作用域，卸载时整域清空。

> 一句话记住：**插件可以改今天的界面，不能改昨天的记录。**

> 重排理由：P18 原验收同时含"契约冻结 + 巨石拆分"，两件大事塞一期风险过高；拆分单独成期（P19），
> 并把需求清单里已落地项（本地模型 / 媒体桥接）与新增拍板项（内置插件、子代理自定义模型）各归其位。

### 关键设计要点

- **浏览器内核**三个性能决定：进程内直持 CDP 会话；DOM 增量 diff 替代全量快照；语义定位（role / name / text）为主，坐标点击仅作兜底。
- **成本观测**：价格表带生效时间，供应商调价不影响历史账目；prompt / completion / cache token 分开计量；另加请求次数、失败率、延迟分位。
- **无头会话**：会话能被程序化唤醒、不依赖 UI，是定时器、Webhook、子代理、主动提醒共同的前提。
- **媒体桥接**：检测到图像 / 音频输入而当前模型不支持 → 路由到配置好的多模态模型 → 结果回注成文本；按内容哈希缓存，避免重复描述同一张图。

## 九、Hooks 机制（已拍板）

价值在于三方面：

- **确定性**：固定规则（工具调用前拦截危险命令、写文件后自动格式化与跑测试、会话结束沉淀记忆、超预算自动降级）不靠模型每轮重想。
- **成本控制**：超预算自动降级。
- **定制出口**：用户不改源码即可定制行为，是开源项目的必要能力。

> 注："决定做"只花一秒，"定义其事件清单"需花一轮迭代。
