# 子代理调度草案 v0（施工单 027 / P18 交付，落地留 P22）

> 目的：P22 动工前把架构衔接点定下来，避免子代理并行打破 P16/P24 刚收敛的并发模型。
> 核心纪律一句话：**子代理 = 独立会话，主会话「一会话一轮」不变量一根手指都不碰。**

## 1. 并行度上限

- 全局并发子代理数上限：`[subagent] max_concurrent`（建议默认 3；0 = 不允许并行）；
- 单父任务的活跃子代理上限：建议 2，防止单任务把额度吃满；
- 排队语义复用 steer 队列形态：满员时派发请求进 FIFO，出队即跑，不丢不串。

## 2. 上下文隔离

- 每个子代理是一条**独立会话文件**（sessions/<uuid>.json，workspace 继承父任务）；
- 子代理的系统消息 = 派发指令（任务描述 + 输出格式要求）+ 与主循环同一套 AGENTS.md /
  prompts/system.md——**看不到**父会话历史、审批记录、检查点；
- 父会话也看不到子代理的中间过程（trace 时间线按会话切分天然隔离）；
- 工具与审批：子代理沿用同一审批门与钩子（session_id 传子会话自己的 id，审计天然分流）。

## 3. 结果合并

- 子代理跑完，**最终回答**（非过程）作为一次工具结果回注父任务（工具名建议
  `subagent_spawn` / `subagent_result`，danger 档 Normal）；
- 合并走无头会话接口（P22 先落地无头：会话能被程序化唤醒、不依赖 UI）——
  无头是子代理、定时任务、Webhook、主动提醒的共同前提，顺序不能反；
- 子代理失败/超时：回注错误文本让父模型重派或换路，不静默、不连坐父任务。

## 4. 成本归属

- P21 台账（`src/usage/`，`logs/usage/ledger.jsonl`）的每条记录已带 `parent_session` 字段
  （v1 恒为 None）；子会话的模型调用填父任务 id 即可按父任务聚合，**无需数据迁移**；
- 报表按「父任务」聚合展示，供应商 → 模型两级不受影响；
- 预算：父任务的 budget_tokens 包含全部子代理花销（防止拆子代理绕过预算）——子会话的
  累计要并进父任务计数（server 侧接线，P22 落地时做）。

## 5. 模型席位（用户直派需求：子代理自定义模型）

- 角色系统已有 main / summary / title / embedding 席位（B3 解析链）；
- 新增 **`roles.subagent` 席位**：未配置 = 回落主渠道（与 B3 一致）；
- 派发时可请求级覆盖（`/api/chat` 已支持请求级 model/base_url，坑 5）——
  典型用法：主 agent 用旗舰模型，子代理跑量用便宜模型；
- 花销按实际用的模型记账（与第 4 节的 parent_session 正交）。

## 6. 不变量与风险

- **主会话「一会话一轮」不动**（steer.rs + CancelRegistry::try_begin）：子代理跑在
  独立会话，天然不触碰该不变量；
- 取消：父任务取消 → 通知取消其全部活跃子代理（子会话自己的 CancelFlag）；
- 审计：subagent.* 事件只增（021 纪律）；影子仓库检查点归属子会话自己的 session_id；
- 风险留口：并行写冲突检测目前按「本轮 tool_calls」判定，子代理各自一轮互不可见，
  落地时需要跨会话写锁（或约定子代理默认只读 + 指定写目录），P22 开工前定。

## 7. 落地顺序建议（P22 内部）

1. 无头会话（程序化唤醒）→ 2. 定时任务（最薄的上层用户）→ 3. 子代理（复用无头）→
4. 主动记忆提醒（复用定时器 + 无头）。
