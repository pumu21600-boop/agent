# 施工单 004：P3 执行沙箱 v1

## 项目背景（自行对齐）
- 依据 `docs/ROADMAP.md`（P3）与总架构 §6（执行沙箱）：**壳先于 shell**。
- P2 已完成（tag v0.3-p2）：核心循环、read_file 工具。P4 才把 shell 工具接进注册表并走审批；
  本单只交付「拉起进程的真实隔离壳」，供 P4 的 shell / 文件写等危险工具共用。
- 目标：不依赖管理员权限，普通用户进程内做到**真实隔离**——Job Objects 管进程树生命周期与资源上限，
  受限 token 管权限面；不做 AppContainer / 网络限制（P12）。

## 任务 A：沙箱模块 + 配置（src/sandbox/、config.toml）
1. `src/sandbox/` 落真实实现，替换占位注释；对外 API（P4 工具层的唯一入口）：
   - `SandboxLimits { timeout_ms, memory_mb, active_processes }`
   - `spawn(application, command_line, working_dir, limits) -> SandboxChild`（可后续 wait/kill 的句柄，Drop 即团灭）
   - `run(...) -> SandboxOutput { exit_code, timed_out, stdout, stderr }`（spawn + 等待的便捷封装）
2. `config.toml` 新增 `[sandbox]` 节：`timeout_ms`（默认 10_000）、`memory_mb`（默认 1024）、
   `active_processes`（默认 64）；缺节走 serde 默认，老 config.toml 不用改。

## 任务 B：受限 token（src/sandbox/token.rs）
1. 取当前进程 token → `CreateRestrictedToken`：`DISABLE_MAX_PRIVILEGE`（剥光全部特权）
   + 受限 SID 白名单（当前用户、Everyone、BUILTIN\Users、Authenticated Users），
   保证工作目录与系统目录正常可达、他人文件与管理员面不可达。
2. 不降完整性等级（低 IL 会挡住 P4 shell 在工作目录内写文件）；AppContainer / 完整性策略留 P12。
3. 全程不需要管理员权限；token 只在拉起瞬间用，句柄用完即关。

## 任务 C：Job Objects（src/sandbox/job.rs）
1. `CreateJobObjectW` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（句柄一关整树必死，孤儿零残留）
2. `JOB_OBJECT_LIMIT_PROCESS_MEMORY`（memory_mb）、`JOB_OBJECT_LIMIT_ACTIVE_PROCESS`（active_processes）、
   `JOB_OBJECT_LIMIT_PROCESS_TIME`（CPU 时间兜底）
3. UI 限制：剪贴板读写、全局原子、桌面切换、句柄管理（JOBOBJECT_EXTENDED_LIMIT_INFORMATION.UiRestrictionsClass）
4. `JobGuard` RAII：Drop = TerminateJobObject + CloseHandle；禁止 breakaway（不设 BREAKAWAY_OK）。

## 任务 D：进程拉起与收割（src/sandbox/proc.rs）
1. `CreateProcessAsUserW`（受限 token）：`CREATE_SUSPENDED` 先挂起 → `AssignProcessToJobObject` → `ResumeThread`
   （挂起期入 job，竞态窗口为零）；`CREATE_NO_WINDOW` + `CREATE_UNICODE_ENVIRONMENT`。
2. stdout/stderr 匿名管道捕获（父端读句柄禁继承），NUL 作 stdin；读管道在独立线程，父端不阻塞。
3. 超时：`WaitForSingleObject` 超时 → `TerminateJobObject`（整树死）→ 标记 `timed_out`。
4. **环境裁剪**：不继承父环境，白名单注入最小集（SystemRoot/COMSPEC/PATH/TEMP/TMP/PATHEXT/
   NUMBER_OF_PROCESSORS/PROCESSOR_ARCHITECTURE/USERPROFILE/LOCALAPPDATA 等）——
   DEEPSEEK_API_KEY 等密钥永不进入子进程。
5. 每次 spawn/run 落 JSONL：`state` 事件 `kind: sandbox.spawn`（app/working_dir/limits，不含命令行敏感内容）/ `kind: sandbox.exit`（exit_code/timed_out/chars）。**不新增 event_type**。
6. 同步阻塞实现；P4 接工具层时用 spawn_blocking 包（本单在 API 注释里写明）。

## 任务 E：验证
1. `cargo test`（真实 Windows 进程探针，MSVC 工具链）：
   - 输出捕获：`cmd /C echo` 结果带回
   - 环境裁剪：子进程 `set` 里看不到 DEEPSEEK_API_KEY / 任何 KEY
   - 特权剥离：`whoami /priv` 无 `SeChangeNotifyPrivilege`（普通用户 token 必有，剥光后必无——差分断言）
   - 工作目录可达：cwd=工程根 `type Cargo.toml` 成功（不能隔离过头）
   - 超时团灭：短超时杀长 ping，`timed_out=true`
   - kill-tree：cmd 里 `start` 出孙进程，Drop 后 tasklist 查 ping.exe 归零
   - 内存上限：powershell 申请超限内存 → 进程失败
2. `GET /api/sandbox/selftest`：跑快速探针（输出/环境/特权/工作目录/超时），返回 JSON 逐项结果，浏览器可直接验收。
3. 文档：`docs/jsonl-schema.md` 补 state kind（sandbox.spawn / sandbox.exit）；ROADMAP 状态表更新；
   README 进度行与沙箱说明；ROADMAP 已知坑补「嵌套 Job」条目。
