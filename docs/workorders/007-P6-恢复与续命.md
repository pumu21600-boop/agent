# 施工单 007：P6 恢复与续命

## 项目背景（自行对齐）
- 依据 `docs/ROADMAP.md`（P6）+ 总架构 §9/§10/§13/§14：git shadow repo checkpoint、
  会话落盘+恢复、HANDOFF 交接。思路：**假设一定会崩，把"能恢复"做成默认**。
- 现状（P5 完成 tag v0.6-p5）：核心循环/沙箱/工具/审批/上下文裁剪齐；
  但会话只活在前端内存（刷新即丢），文件改动无快照可回滚，崩溃后无交接物。

## 任务 A：git shadow repo checkpoint（src/recovery/）
1. 影子仓库：`<workspace>/.agent/shadow`（独立 git dir，workspace 为 work-tree），
   初始化时落本地 config：user.name/email、core.autocrlf=false、commit.gpgsign=false。
2. 只跟踪**真仓库已跟踪文件**（`git ls-files`），加排除规则（node_modules、target、dist、
   logs、.agent、大二进制 >10MB 跳过）；pathspec 走 `--pathspec-from-file`（防 Windows 命令行长度）。
3. `checkpoint(reason)`：add + 有变更才 commit，返回 {id, ts, reason}；无变更/非 git 仓库/失败
   → 记 JSONL 并跳过，**绝不阻断工具执行**。
4. 挂钩点：核心循环里 danger≥1 的工具（write_file/shell/git）审批通过后、执行前各拍一次。
5. `list(limit)` / `restore(id)`：restore 用 `reset --hard <id>` 恢复工作树（含删除 checkpoint
   之后新建的已跟踪文件）；shell 副作用不可回滚，边界写进文档。
6. JSONL：state `checkpoint.created` / `checkpoint.restored` / `checkpoint.skipped`。

## 任务 B：会话落盘 + 恢复（src/session/）
1. `Store`：会话消息数组（OpenAI 格式，不含 system）落 `<workspace>/logs/session.json`，
   原子写（tmp+rename），带 updated_at。
2. 落盘点：任务开始（用户消息进）、每步工具回填完、任务终止（Done/Cancelled）——
   核心循环发新事件 `AgentEvent::Snapshot { messages }`，server 收到即落盘。
3. 恢复：GET /api/session 返回落盘消息；前端启动时拉取重建对话视图
   （user 气泡 / assistant 正文+工具列表，tool 消息按 tool_call_id 配对成预览）。
4. 新会话：DELETE /api/session 清盘；前端侧栏「新会话」按钮（带确认）。
5. JSONL：state `session.saved` / `session.cleared`。

## 任务 C：HANDOFF 交接（src/recovery/）
1. `write_handoff(...)`：生成 `<workspace>/HANDOFF.md`，**头部强制**：项目名、git remote、
   HEAD commit 哈希、时间戳、session_id、触发方式；正文 v1 从简：最近用户请求（≤5）、
   最后一条助手回答摘要（前 500 字）、本会话工具调用计数。不调模型（蒸馏 P7 再说）。
2. 触发：手动 POST /api/handoff（server 从 session.json 读消息）；自动——每轮上下文占用
   ≥ 80% 预算时每任务触发一次，SSE notice + JSONL `handoff.written`。
3. HANDOFF.md 与 .agent/ 进项目 .gitignore（不污染工作树）。

## 验收标准（全过才算完）
1. write_file/shell 改文件前有 checkpoint.created；无变更时 skipped；非 git 目录优雅停用
2. 改几个文件 → list 能看到 → restore 后工作树回到 checkpoint 时刻（含删除新建文件）
3. 发两轮对话 → logs/session.json 有全量消息（含 tool_calls/tool）；重启服务+刷新页面 →
   /api/session 恢复对话；DELETE 后清空
4. 手动 POST /api/handoff → HANDOFF.md 头部四要素齐；构造超 80% 预算 → 自动触发一次不重复
5. cargo test 全绿（checkpoint 创建/恢复/排除规则、session 原子写/清空、handoff 头部字段均有单测）

## 禁止事项
- 不自研快照格式（文件兜底统一走 git）
- 不做语义摘要/蒸馏（P7）；不做多会话切换（P10）
- 不改 6 类 event_type；不动审批三档与沙箱
- checkpoint 失败不得阻断工具执行；restore 不碰用户真仓库的 HEAD/分支
