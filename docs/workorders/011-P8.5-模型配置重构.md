> （第一节阶段状态 + 第四节已知坑）和 `git log --oneline` 对齐进度。

## 项目背景（自行对齐）

模型配置 = `src/config/settings.rs`（Settings/Config 结构、镜像同步、key 存储）+
`src/server.rs` 的设置 API（get/put_settings、manage_configs、config_state_json、
find_channel/build_chat_params）+ `web/src/App.svelte` 设置面板 + 根目录
`providers.json` 供应商预设。经 P0→P8.4 八个阶段增量堆叠，能跑但结构已经欠债。

## 现状痛点（重构靶子）

1. **双份状态 + 位置元组同步**：`Settings` 顶层镜像字段（provider_id/base_url/model/
   models/context_length/max_output_tokens/temperature/top_p/thinking/thinking_style）与
   `configs[]` 每项同名字段各存一份，靠 `sync_config_from_mirror()` 的**位置元组**
   （snap.0…snap.9）和 `activate()` 的逐字段手抄同步。加/删一个字段要改 5 处
   （两个 struct、快照元组、activate、put_settings、UI）——P8.4 删 thinking_budget
   实际改了 6 个文件点，就是这种散弹式修改的实证。
2. **清除语义三套并存**：`0`=清除长度（context_length/max_output_tokens）、
   `-1`=清除采样（temperature/top_p）、`""`/`auto`=清除思考（thinking/thinking_style）。
   前后端各记一套特判，P8.3 还因此吞过思考档位（已修，见 ec8a40a）。
3. **/api/settings 响应是手拼 40 键大 JSON**（config_state_json），前后端字段漂移
   无编译期保障；请求侧 SettingsUpdate 16 个全 Option 字段靠约定当 PATCH 用。
4. **key 存储以归一化 base_url 为键**（keys: BTreeMap<String, DPAPI密文>），换渠道
   地址即"丢"key 的 UX 怪象；v1/v2 旧格式迁移代码仍背着。
5. providers.json 预设与网关端点探测（gateway::compat）的边界是清楚的——
   配置层只管存储与 UI，重构**不得越界进网关**。

## 任务

**方案先行**：先出重构设计提案（数据结构、API 形状、清除语义、key 键策略），
列清"删什么/留什么/迁移什么"，**用户拍板后再动工**。方向参考（非强制）：

- A. 消灭镜像双份状态：唯一事实源（active config 或独立 active 字段）+ 派生视图，
  用 serde/类型设计让"加字段只改一处"成为结构保证；位置元组必须消失。
- B. 清除语义统一成一种（显式 null 或显式 op 字段），前后端一处定义。
- C. /api/settings 请求/响应走类型化结构（serde 双向），删手拼 JSON。
- D. key 键策略评估：按配置 id 存 key（configs[].key_cipher 已有 per-config 先例），
  v1/v2 迁移代码能否删除需给出证据（旧文件实测可加载）。

## 验收标准

1. 旧 `settings.json`（v2.4，含已删字段如 thinking_budget）加载不丢配置不丢 key；
   DPAPI 密文格式与既有迁移路径不破坏。
2. `cargo test` 全绿（现基线 57 个），且镜像同步/配置切换/换渠道作废模型清单
   三条机制有直接单测覆盖。
3. 手工回归：新建配置→填 key→拉模型→勾选→切换→删除；换 base_url 清空模型清单；
   防抖保存切配置前 flush；思考档位（low/medium/high）持久化不回退（P8.4 修复项）。
4. 改了前端必须 `cd web && npm run build`，并起服务冒烟（http://127.0.0.1:8321）。
5. 小步提交，一条功能点一条，中文 message 前缀 `P8.5: ...`。

## 禁止事项

1. 不动 6 类 JSONL 事件 schema、DPAPI 存 key 机制、`providers.json` 思考词表
   （P8.4 刚定稿）、网关 `build_body`/`compat`/`effort`/`replay`/`tags`。
2. `settings.json` 永不入库；持久化仍是单文件 JSON（不上数据库/异步运行时改造）。
3. 不改 `rust-toolchain.toml`（本机 GNU 工具链损坏，钉死 MSVC，见 ROADMAP 坑 1）。
4. 不动 `AGENTS.md`（产品原则：留给用户自填）。
