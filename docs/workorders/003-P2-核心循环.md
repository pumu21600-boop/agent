# 施工单 003：P2 核心循环 v1

## 项目背景（自行对齐）
- 依据 `docs/ROADMAP.md`（P2）与总架构 §4（核心循环刚性）/ §5（工具系统）
- P1 已完成（tag v0.2-p1）：模块骨架、providers 数据化、聊天 UI。本单填进 `core/` 与 `tools/`。

## 任务 A：模型驱动的 agentic 循环（src/core/agent.rs）
1. 循环：组装 messages → 调模型（带 tools）→ 解析：纯文本则终止；含 tool_calls 则执行→回填→继续
2. 硬约束：步数上限（config `[agent] max_steps` 默认 8）；每步开始与每个流式分片前查取消标志，已取消立即终止
3. system prompt 外置 `prompts/system.md`（数据驱动，不焊死 Rust 字符串）
4. 会话：请求携带完整 messages 数组（user/assistant/tool），服务端无状态；跨请求历史仍不持久化（P6）

## 任务 B：网关支持工具调用（src/gateway/）
1. 请求体带 `tools`；流式响应累积 `delta.tool_calls`（按 index 合并 id/name/arguments 分片）
2. stream_chat 返回聚合结果：content / reasoning / tool_calls，保留 model_chunk 日志
3. JSONL 新增事件全量使用：`thought`（完整思考）、`tool_call`（名称+参数）、`tool_result`（结果摘要）

## 任务 C：工具注册表 + 第一个工具（src/tools/）
1. `ToolSpec { name, description, parameters_schema, danger_level }` + 注册表查表
2. 内置第一个工具 `read_file`：仅允许读工作目录内文件（路径穿越校验），结果超长按 `[agent] tool_result_max_chars`（默认 8000）截断
3. 未知工具名 / 执行失败：以 error 结果回填模型，不中断循环

## 任务 D：接口与前端
1. `POST /api/chat` 请求体改为 `{messages:[{role,content}], model?, base_url?}`；SSE 新增 `{"tool_call":{name,args}}`、`{"tool_result":{name,preview}}`
2. 聊天界面：助手消息内渲染工具卡片（执行中/完成/失败三态）、思考折叠保留
3. 禁止：加写文件/shell 工具、审批、沙箱、记忆、多会话

## 验收标准（全过才算完）
1. mock 渠道驱动：模型先返回 read_file 工具调用，前端出现工具卡片并执行；回填后模型给出最终回答，流式显示
2. JSONL 可查 thought / tool_call / tool_result 事件且 payload 符合 schema
3. 步数上限生效（mock 无限要工具时循环在第 N 步强制终止）；执行中点「停止」立即中断
4. read_file 越界（../ 或盘符绝对路径）被拒绝并回填错误
5. 换模型即时生效仍成立；重启服务不残留对话

## 禁止事项
- 不做写工具 / shell / 沙箱 / 审批（P3/P4）
- 不改 JSONL 6 类事件 schema
- 不做皮肤活
