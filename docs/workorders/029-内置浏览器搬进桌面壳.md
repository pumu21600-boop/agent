# 029 ·  内置浏览器搬进桌面壳（child webview 宿主 + CDP 驱动 + 无头兜底）

> 起因：用户拿来一份外部方案《tauri内置浏览器方案.md》（Tauri child Webview + WebView2 CDP，参照 ZCode 四层架构写的方案），问「这个方案在我们的项目能不能行」。
> 评估结论：**CDP 技术路线可行，但不能照抄**——外部方案假设「Tauri 就是应用本体」，而本项目 agent.exe（axum）才是真源、壳只是个加载 5173 的薄窗口、浏览器内核（约 130KB）在服务进程里且被 agent 工具与面板共享。照抄会把内核搬进壳进程，agent 工具立刻失去驱动能力。
> 落地形态：**内核不动，壳退化为 child webview 宿主**。

## 一、架构（三方职责）

| 方 | 职责 |
|---|---|
| agent.exe（服务）| 浏览器内核唯一 owner：全部 CDP 会话、tab 状态、协议（/ 原样）；经控制通道指挥壳 |
| desktop 壳 | child webview 宿主：只执行 create/close/rect/visible/devtools/reset，不决策生命周期 |
| web 面板 | 壳里渲染真页面（占位区 + 矩形同步）；普通浏览器打开仍走 screencast 帧流 |

**控制通道**：127.0.0.1:9225，换行分隔 JSON，单向（服务→壳）。create 的确认靠 /json/list 出现新 target，其余指令幂等，故无需 ack。
**CDP 端点**：壳 WebView2 环境带 `--remote-debugging-port=9223`（tauri.conf.json 的 additionalBrowserArgs），child webview 带同一份 args 复用同一环境（wry 每个 webview 各自 CreateCoreWebView2EnvironmentWithOptions，options 一致才共用 browser 进程）。

## 二、关键决策与真机踩坑（全部实测 Edg/153.0.4234.48）

1. **child webview 一律 about:blank 起步，导航走 CDP Page.navigate**。带初始 URL 创建时，导航一提交 CDP target 就被换掉——50ms 轮询实测：target 上线约 180ms 后从 /json/list 消失，CDP 连上即断（"actor 已退出"）。about:blank 起步 + CDP 导航的 target 全程稳定（example.com → iana.org 点击跳转都没换 id）。
2. **reset 后必须等旧 target settle 再建新 webview**。壳不重启而服务重启时，上一个会话的 webview 还活着；直接 reset+建新，新 webview 的 target 会跟着旧 webview 的异步销毁（~180ms）一起从列表消失。且**一旦进入这个状态，壳会持续退化**（后续所有 child webview 的 target 都不稳），只能重启壳。故 `wait_targets_settled()`：reset 后轮询到非壳内部 target 归零再建。
3. **发现基线要快照全部 page target id**（不是只看自己的 tab）。壳重启后 9223 复生，旧连接的 actor 早已退出——僵尸 tab（title/url 全空）会骗过 `browser_alive(port)` 探活。两件事兜住：① `all_page_target_ids()` 发 create 前快照，只认快照后新出现的；② `Cdp::is_alive()`（actor 退出即假）+ `ensure_session` 摘死 tab，全死就重建会话。
4. **端口参数不带 DPI/渲染类 flag**。外部方案给主窗口带 `--force-device-scale-factor=1`——additionalBrowserArgs 作用于整个 WebView2 环境，会把你自己的 UI 缩放摁在 100%。本单只带端口 + 环回地址，并保留 wry 默认的 `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`。
5. **child webview 能开真 DevTools**（`Webview::open_devtools`，tauri 需 devtools feature）——补上无头时代「无头页面没有真 DevTools」的缺口，面板「⋯ → 开发者工具」。注意：WebView2 的 DevTools 窗口与页面共用同一个 browser 进程，**杀 DevTools 进程会连整个 browser 进程一起杀**（正常点关闭不会）。
6. **WebView2 在 CDP Page 域启用时不弹原生对话框**——alert/confirm 只走 `Page.javascriptDialogOpening`，面板弹窗条是唯一 UI，不会出现「原生框 + 面板条」双 UI。但弹窗开着时页面脚本全阻塞（隔离世界求值也跑不了），`panel_state`/`panel_screenshot`/`tab_title_url` 都要先查 dialog 再求值，否则每个 eval 白等 10s 超时。
7. **用户点击链接导致的导航不走 navigate_tab**，隔离世界 contextId 缓存会失效——`Page.loadEventFired/frameNavigated` 事件主动清缓存 + `evaluate_in_isolated_world` 调用失败也清缓存重试一次（遗留隐患，壳里真点页面更容易踩）。
8. **add_child 只能在非主线程调用**（内部 run_on_main_thread + recv，主线程调用死锁）——壳的控制通道读线程是 std::thread，正好。set_position/set_size/show/hide 走 dispatcher，任意线程可调。
9. **单实例守卫**：两个壳会抢 9223（第二个的环境绑不上端口，它的 webview 不可见也不可驱动）。占 127.0.0.1:9224 + PID 锁文件探活，第二个壳直接退出。**故障模式（补丁修）**：9224 被无关程序占用时不能拒绝启动——第一版读不到锁里的 PID 就默认按活着处理直接 exit，等于一个无关端口能把整个壳拦死。改为**先读锁再写锁**（写在自己 bind 成功之后，否则第二个壳会覆盖第一个壳的 PID、把自己误判成"没有别的壳在跑"），占用者确认不是本壳就打日志放弃守卫继续启动。
10. **弹窗防护**：child webview 注入 `window.open = () => null` + `on_new_window → Deny`，避免页面弹新窗口。
11. **壳里 webview 的显隐门控**（补丁，用户截图发现后修）：`visible_tab` 是 agent 工具与面板共用的老状态（无头时代只驱动 screencast），**不等于「人在看」**——agent 的 new_tab/activate_tab 也写它。不门控的话 agent 一开工就把 webview 弹到聊天区上空（真机复现：面板关着时建页，webview 以默认矩形 0,0,1024×768 浮在界面左边，用户截图质问"浏览器不在侧边栏"）。改为两道门控：① `panel_showing`——只有面板自己的 activate/new/viewport/frame/navigate 能置真，agent 工具不置；② 矩形未知不显示——首次打开/切页签的 350ms 防抖窗口里先藏着，防错位闪现。矩形一到就立即同步显隐（`panel_viewport` 里直接调 `sync_shell_visibility`），不等最多 5s 的巡检。
12. **原生模式下网页内容的浮层会被 child webview 盖住**（补丁，用户反馈"三个点点了没反应"）：child HWND 的 z-order 永远在主 webview 内容之上，任何往 `.web-body` 区域里弹的浮层（下拉菜单/气泡）都会被盖住——实测「⋯」菜单往下弹 101px，其中 78% 落在 webview 区域里，只剩顶端 22px 露出来，看起来就是"点了没反应"。修法不是改定位（往上弹会被窗棂裁 14px、往左弹又脱锚），而是**菜单开着的时候先让壳把 webview 藏了**（走即有的 activate '' / activate id 通道），关掉再恢复。规律：**原生模式下，任何盖住 body 区的网页浮层都要考虑这条 z-order 铁律**。

## 三、降级路径（壳不在时行为不变）

- 壳没跑 / 控制通道断 / CDP 端口探不通 → `launch()` 回落无头 Edge（自拉实例、随机端口、临时 profile）。
- 用户从普通浏览器开 5173：后端 `state.mode = shell` 但客户端不在 Tauri → 面板继续 screencast 帧流（`webNative` 判定 = mode==='shell' && 在 Tauri 里）。
- screencast 门控：只有「15s 内有客户端轮询帧」才给可见页开 `Page.startScreencast`——壳里看真页面不白编码；壳外客户端一轮询自动恢复。

## 四、验证记录（真机，2026-09-22）

壳 + 服务全新启动：CDP 9223 列出壳 UI target ✓；建页 target 稳定 ✓；截图 PNG 40KB ✓；screencast JPEG 帧 ✓；点击 example.com 链接跳到 iana.org ✓；本地 fixture 页 type/key/scroll ✓；多标签建/切/关 target 同步 ✓；连续 8 建 6 关无退化 ✓；服务重启 4 轮（reset+settle）全部健康 ✓；真实 UI 点「网页」页签 → webview 落位面板区（868,127 404×725）✓；原生模式 DOM（.web-native 占位、0 个 img）✓；alert 弹窗 CDP 捕获 + 面板 51ms 响应 + 无原生窗口 ✓；杀壳 → 自动回落无头（独立端口，example.com 正常）✓；第二个壳被守卫拦下 ✓；真 DevTools 窗口打开 ✓。

13. **没有壳时不再自动拉无头 Edge**（用户反馈「为什么还是拉起了edge」后改）：用户多次明令不要起 Edge 进程，而 start.bat 原本只起服务不起壳——默认流程里没有壳，浏览器只能回退拉 Edge，等于既定的承诺在默认路径上不成立。三件事一起修：① `launch()` 无壳时直接返回人话错误（「桌面壳没运行……确需无头模式设 AGENT_BROWSER_HEADLESS=1」），不再静默起 Edge；② `start.bat` 改为优先起壳（壳自己保活服务），壳没构建才回落老行为；③ 无头子进程挂 **Job Object（KILL_ON_JOB_CLOSE）**——服务被硬杀（stop.bat 走 taskkill /F）时 Edge 跟着死，不再留孤儿（真机踩过：用户机器上一个提权实例留下的孤儿 Edge 连任务管理器都杀不动）。另修两个顺带爆出的雷：**壳关窗改为隐藏到托盘**（原来关窗=进程退出，浏览器宿主连同 CDP 端口一起没；用户习惯点 X），以及 **就存在的 service_exe 路径 bug**（desktop/ 多退一级指向 Desktop\target\release，壳从来没能自己拉起过服务——以前服务总是手动起的所以一直没暴露）。
14. **`.bat` 必须纯 ASCII**：cmd 按 OEM 代码页读 .bat，UTF-8 中文会变乱码并被当成命令执行（start.bat 里一行中文 echo 直接把批处理炸了）。仓库里现有 .bat 全英文就是这个原因。

## 五、已知限制

- 壳窗口最小化/隐藏时渲染停摆，agent 截图可能拿到黑帧（无头模式无此问题）；点击/输入/快照不受影响。
- WebView2 browser 进程崩溃（罕见）会把壳的 UI 一起带走，壳进程不退不重启——用户需重开壳（Tauri v2 无自动恢复面）。
- 9223 暴露在本机环回：本机任意进程可经 CDP 控制壳内页面（含 UI 自身）。本地优先工具的信任边界内可接受，发布打包时应改高位随机端口。
