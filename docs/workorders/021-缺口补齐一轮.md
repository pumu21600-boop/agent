# 施工单 021 —— 缺口补齐一轮（用户直派，2026-09-17）

## 起因

用户问「现在项目缺什么」后指示：**除桌面壳外，进行一轮大补充**。依据是当时盘点出的缺口清单
（架构留口未做、工程质量欠账、本机状态三类）。

## 目标

1. 把「架构里许诺但没做」的洞补上：组件总线（UI 插槽）、MCP 非 stdio transport、WASM ABI 歧义。
2. 把工程质量欠账清掉：clippy 归零、CI、单测覆盖安全关键路径、eval 任务集、LICENSE、版本号、发布打包。
3. 让**发布形态真能跑**：exe 不再依赖编译期源码目录。

## 禁止事项

- 不碰桌面壳（用户明确排除）。
- 不改既有 JSONL 事件 schema、不改 settings.json 既有字段语义（只增不改）。
- 审批三道防线（风险分级、首装确认、Plan 拦截）语义一律不动。
- 不自行提交/推送（项目纪律：用户要求才提交）。

## 交付

### A. 运行形态（本轮最关键的一处）

- **`config::app_root()`**：exe 同级有 `config.toml` 或 `web/` ⇒ 认定随包运行，config.toml /
  settings.json / providers.json / prompts / web/dist / plugins / logs 全落在 exe 同级；
  否则回落 `CARGO_MANIFEST_DIR`（`cargo run` 与 `target\release\agent.exe` 直接跑行为不变）。
  改动面：`main.rs`、`config/settings.rs::path()`、`tools::workspace_root()` 默认值。
- **`scripts/package_release.ps1`**：cargo build --release + npm run build → 组装
  `dist/agent-<版本>-win64/`（exe / web/dist / prompts / plugins / ui-ext / config.toml /
  providers.json / tools/git-runtime.zip / start.bat / stop.bat / README / LICENSE）+ 打 zip。
  真机验证：把整包拷到 `%TEMP%\agentdist` 独立运行，`root` 指向包目录、UI 来自包内 dist、
  settings.json 与 logs 落在包目录（不写回源码树）、沙箱自检 5/5 通过。
- **探针假失败修复**：`probe_workspace_read` 原先写死读工作区的 `Cargo.toml`，打包形态（无源码）
  必然报 FAIL —— 改为探针自带标记文件（写完读回再删），两种形态都真验证「工作目录可读」。

### B. 组件总线 v0（UI 插槽，架构 §7 的最后一块留口）

- 后端 `src/plugin/ui.rs`：扫描 `<应用根>/ui-ext/` 与 `<当前工作区>/ui-ext/`（同名工作区优先），
  每个目录一份 `manifest.json`（title/description/version/entry）+ 入口页；
  `resolve_asset` 做**路径穿越硬拦**（拒绝对路径/`..`/盘符，canonicalize 后必须在扩展目录下）。
- 路由：`GET /api/ext`（清单）、`GET /ui-ext/{name}`、`/ui-ext/{name}/`、`/ui-ext/{name}/{*path}`（静态分发）。
  尾斜杠那条必须有，否则请求掉进 SPA 兜底、把整个应用套进 iframe（真机抓到）。
- 前端：设置新增「扩展」分区（卡片 + 打开）+ 右侧 `.ext-panel` 面板承载
  `sandbox="allow-scripts"` 的 iframe（不透明源，拿不到宿主 DOM/localStorage，也 fetch 不到 /api）；
  唯一通道是 postMessage 白名单只读桥：`app.info` / `workspace.info` / `workspace.files` /
  `git.status` / `memory.search` / `session.info`（写操作一律不在桥里）。
- 参考扩展 `ui-ext/board/`（项目速览）：真机浏览器验证——面板内显示的版本/运行根/会话/工作区
  全部来自宿主桥，iframe 内的按钮点击同样走桥返回。

### C. MCP transport 补全

- `McpServerCfg` 增 `transport`（stdio|http，默认 stdio，向后兼容）/`url`/`headers`（键值只在内存与
  settings.json，绝不进日志）。
- `mcp.rs` 增 **Streamable HTTP**：POST JSON-RPC；响应支持 `application/json` 单包与
  `text/event-stream`（解析 `data:` 帧、按 id 取匹配帧，心跳/注释/串扰帧跳过）；`Mcp-Session-Id`
  从 initialize 响应头拿到后在同 server 后续请求回带；传输层失败标记离线（下次重连重握手），
  协议层错误照原样上报。
- 保存校验：http 必须有 http(s) url、stdio 必须有 command（早失败好过调用时才报错）。
- 测试：SSE 帧解析、HTTP 端到端（进程内 mock：initialize→JSON+会话头、initialized→202、
  tools/list→SSE、tools/call→SSE 含串扰帧）、连不上必须报错且不留在「在线」态；
  真机冒烟 `evals/mcp-http-server.mjs`（JSON 与 SSE 双模式）→ refresh 均 `tools_found: 2`，
  mock 侧日志确认会话头回带。

### D. WASM ABI v1

- v0 把 action 与 payload 写在同一个缓冲区、四参数传 `(ptr,len,ptr,len)` ⇒ action 形同虚设。
  v1 改为一次 alloc 申请 `action+payload` 连续区、四参数各指其位（读第 3/4 参数的插件行为不变，
  随包 hello.wat 忽略参数不受影响）。
- 测试：`abi_layout` 布局纯函数 + **端到端**（临时目录写 wat → scan_and_load → call_tool，
  插件回吐 payload，宿主按值断言 tool/args 正确——若两段共用指针这里会回吐 `call` 而失败）。

### E. 工程质量

- **clippy 归零**：103 → 69（上一轮）→ **0**（本轮；含 clippy --fix 误删 `#[cfg(test)]` 用到的
  导入导致编译失败一次的修复——教训：`--fix` 后必须编译一次）。
- **CI** `.github/workflows/ci.yml`：windows-latest，clippy `-D warnings` + `cargo test --no-fail-fast`
  + 前端 `npm ci && npm run build`。
- **单测补充**（安全关键路径此前零覆盖）：`sandbox/job.rs`（回读内核里的 Job 上限与 UI 限制，
  不只看「设置没报错」）、`sandbox/token.rs`（受限 token 启用特权白名单外为空、登录会话 SID 存在）、
  `service.rs`（tasklist CSV 解析、端口探针）、`config`（app_root 开发形态回落）。
- **eval**：断言类型 5 → 7（新增 `file_not_contains`、`files_unchanged`，快照改用内容指纹）；
  任务集 3 → 9（编辑既有文件 / 删文件 / 多文件脚手架 / 修 bug / 检索报告 / Plan 档写保护 /
  跑测试报告）；新增「仓库任务集校验」测试（断言类型在册、任务名唯一、提示词非空）。
- **版本与法务**：`Cargo.toml` 0.1.0 → 0.14.0（与 tag 对齐）；新增 MIT `LICENSE`；
  `GET /api/version` + 侧栏底部版本行（tooltip 显示运行根）。
