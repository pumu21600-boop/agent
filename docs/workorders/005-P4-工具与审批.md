  本单把第一批工具接进壳，并落审批三档。key 按配置独占（v2.4）、网关自愈均已就位。

## 任务 A：工具注册表扩展（src/tools/）
1. `ToolSpec` 沿用 danger_level（0=read 1=write 2=exec）；执行入口改异步：
   `execute(ctx, name, args) -> Result<String>`，`ToolCtx { cancel, approval, sandbox_cfg, tool_result_max_chars }`。
2. `write_file`（danger 1）：`{path, content}`；限工作目录内（canonicalize 穿越拒绝）、自动建父目录、
   内容上限 512KB；返回写入字节数。
3. `shell`（danger 2）：`{command, timeout_ms?}`；**走沙箱** `cmd /C`，cwd=工作目录根；
   timeout_ms 可选（上限 300_000，默认取 [sandbox].timeout_ms）；输出按 tool_result_max_chars 截断；
   非零退出码/超时如实回填（timed_out 标注）。
4. `search`（danger 0）：`{query, path?}`；rg 可用用 `rg -n -m 50`，否则 findstr /s /n /i 兜底；限工作目录内。
5. `web_fetch`（danger 0）：`{url}`；仅 http/https；GET 拉取，HTML 去标签出正文（script/style 剔除），
   按 tool_result_max_chars 截断。
6. `git`（danger 2）：`{args}`；沙箱内跑 `git <args>`，cwd=工作目录根。
7. 沙箱环境 PATH 改为继承父进程 PATH（PATH 非密钥，git/cargo/node 要能用；其余白名单不变）。

## 任务 B：审批三档
1. 档位定义（纯函数 `needs_approval(mode, danger)`，单测覆盖）：
   - `suggest`：danger 0 自动，1/2 需审批
   - `auto-edit`：danger 0/1 自动，2 需审批
   - `full-auto`：全自动
2. 默认档位 `config.toml [agent] default_approval`（默认 auto-edit）；`/api/chat` 请求级 `approval_mode` 可覆盖。
3. 需审批时：生成 approval id → SSE 发 `{"approval_request":{id,tool,args}}` →
   挂起等待决定（select 取消标志；120s 超时视为拒绝）→ 拒绝则以「用户拒绝了该操作」回填模型，不中断循环。
4. `POST /api/approvals {id, approved}` 决定入口；pending 表存 oneshot sender。
5. JSONL：state 事件 `kind: approval.requested` / `approval.decided`（不新增 event_type）。

## 任务 C：前端
1. 侧栏加档位切换（suggest/auto-edit/full-auto，localStorage 记忆），随 /api/chat 发送。
2. 工具卡片支持审批态：收到 approval_request 就地渲染「允许/拒绝」按钮，点击 POST /api/approvals，
   按钮即失效；结果卡片沿用现有三态。

## 验收标准（全过才算完）
1. full-auto 下：模型能 shell `echo`/`dir`、write_file 落盘、search 命中、web_fetch 抓到正文、git status 正常
2. write_file / search 越界路径被拒绝；web_fetch 非 http(s) 被拒；shell 超时被团灭并如实回填
3. suggest 档：shell 调用触发审批按钮，拒绝后模型收到「用户拒绝了该操作」并继续；auto-edit 档：写文件自动过、shell 要批
4. 审批等待期间点「停止」立即中断；120s 不决定自动拒绝
5. JSONL 不新增 event_type；key/密钥不进沙箱环境与日志
6. cargo test 全绿（含新的 needs_approval / write_file / search / shell 沙箱用例）
