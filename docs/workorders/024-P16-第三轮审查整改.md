## 交付

### A. 同会话并发防护（报告 N1）

- `core/cancel.rs`：`begin()`（同一会话静默换绑）改为 **`try_begin()`**——判定与登记在同一把锁内，
  同一会话已有在跑的一轮时返回 `None`。注册表不再提供静默换绑的路径，旧轮始终握有自己的取消入口。
- `server.rs` `chat()`：进入 handler 即 `try_begin` 抢占；抢不到 → **409 Conflict**
  （`{"error":"会话 <id> 正在运行中：先停止或等它跑完再发（同一会话不支持并发）"}`）
  + JSONL `state/chat.rejected`（reason=session_busy）。登记完成的标志移交 `CancelRun::from_flag`
  RAII 守卫，任务结束（正常 / 提前 return / panic）自动注销，不留僵尸占位。
- 返回类型 `Sse<…>` → `Response`（409 与 SSE 二选一）。
- 前端（`web/src/App.svelte`）：`!res.ok` 时解析服务端 JSON 的 `error` 文案并原样显示
  （409 不再被伪装成「[连接错误] HTTP 409」）。
- 单测：`cancel.rs` 用例改为断言「同会话二发被拒」「被拒请求不复位在跑标志」「迟到的旧轮 end
  不注销新轮」「上一轮结束后可重新开始」；`cancel_all_hits_every_running_session` 同步改用 `try_begin`。

### A2. 同会话并发：从「拒收 409」改为「运行中追加」（用户反馈，同日修正）

用户看过 A 之后指出：同一会话没跑完时**应该能继续发消息，而不是被拒**，前提是不打断原来那一轮。
据此把行为改成 steering：

- 新增 `core/steer.rs::SteerQueue`：会话级追加消息队列（按 `session_id` 归属，先进先出）。
- `ApprovalGate::take_steering()` 默认空实现；核心循环**每个决策点**取一次队列，取到就并入本轮
  对话（模型下一步就看到）→ `AgentEvent::Steer` → SSE `steer`（前端补用户气泡）+ Snapshot 落盘。
- `/api/chat` 遇到同会话在跑：不再 409，文本消息进队列并立刻回 `{"session","notice","done"}`；
  **带附件**的追加仍拒（媒体流水线在轮首一次性构建），明确报错而不是悄悄丢附件。
- 收尾补漏：一轮结束时还没被消费的（最后一个决策点之后才到的，最常见的是「回答正在流式输出时
  用户又发了话」）→ 用最后一轮快照当上下文，紧接着再跑一轮，同一个 SSE 流；**出错**也照样跑掉
  排队消息（用户发出去的话不能被上一轮的失败吞掉）；**用户点停止**则把队列一并作废。
- 前端：输入框运行中不再禁用（发送按钮照常可用），运行中发送走 `steer()`——只补自己这条用户
  气泡、不新开助手气泡（回答接在当前流里）；别的窗口发的追加消息由 SSE `steer` 事件补气泡，
  本页自己发过的按内容配对去重（`localSteers`）。
- 不变量没变：同一会话仍然只有一轮在跑（会话文件单写者、取消入口不被顶掉），追加消息只是
  「给正在跑的那一轮加话」。
- 真机（临时实例 + mock）：① 慢流跑着时同会话再发 → 回执 200「已并入正在运行的一轮」，原流
  推完 30 片后**接着把追加消息跑完**并 `done`，会话文件里两条用户消息与两轮回答都在（上下文连续）；
  ② 多步运行（slow-loop 每步 1.5s）中第 4 步并入（JSONL `steer count:1 step:4`），mock 网关请求里
  能看到追加文本，运行正常收尾。
- 已知边界：追加消息目前是纯文本（带附件走明确报错）；多标签页场景下，回答出现在**跑着的那条流**
  （也就是发起轮次的窗口）里，发消息的另一个窗口要刷新会话才能看到回答。

### B. `edit_file` 体积上限（报告 N2）

- `tools/mod.rs`：新增模块常量 `MAX_FILE_BYTES = 512KB`——`write_file` 的 content、`edit_file`
  的目标文件与编辑结果共用同一上限。`edit_file` 三道闸：`new_string` 超限 → 拒；目标文件超限 →
  拒绝整文件读入；编辑后结果超限 → 拒绝落盘（原文件不动）。
- 单测 `edit_file_rejects_oversized_file_and_result`（超限文件拒读且原文件字节不变 + 结果越界拒写）。
