# 施工单 010：网关补全

## 项目背景（自行对齐）
- 依据 `docs/ROADMAP.md`+ 总架构 §8/§16：角色映射、采样参数、限流、降级链、
  供应商预设补全、思考参数按厂商适配。
- 现状（完成 tag v0.8-p7）：网关单实现（OpenAI 兼容 /chat/completions），
  429 指数退避、客户端热重建（Clash 自愈）、反代 `<think>` 剥离已就绪。
  缺口：请求体只有 max_tokens（无采样参数/思考参数）；摘要等辅助调用与主对话共用同一渠道；
  主渠道挂了就报错（无降级）；本地无限流（只能被动靠 429 退避）；预设缺 5 家。

## 任务 A：providers.json 数据化扩展 + 预设补全（src/gateway/providers.rs）
1. 每个供应商新增可选行为字段（全部 `#[serde(default)]`，旧文件兼容）：
   - `reasoning_style`：`reasoning_content`（默认，思考走独立字段）| `thinking_param`
     （请求端用 thinking 参数族，GLM 对象形态）| `effort_param`（请求端用 reasoning_effort，
     OpenAI 风格）| `in_content`（思考混在正文 `<think>` 里，剥离已兜住）。
   - `enable_thinking_param`：布尔开关参数名（Qwen 系 `enable_thinking`）。
   - `thinking_budget_param`：思考预算参数名（Qwen 系 `thinking_budget`）。
   - `reasoning_counts_in_max_tokens`：思考是否占 max_tokens（GLM 实测占=true，Qwen 官方不占=false）。
2. 预设补全：openrouter / gemini（OpenAI 兼容端点 v1beta/openai）/ lmstudio / mnn / llamacpp。
   本地服务（lmstudio/mnn/llamacpp）默认 key 可空。
3. /api/providers 透出新字段（前端按它渲染思考开关是否可用）。

## 任务 B：请求参数结构化 + 思考参数适配（src/gateway/mod.rs）
1. 抽 `ChatParams`（max_tokens / temperature / top_p / thinking: Option<String>("on"/"off") /
   thinking_budget: Option<u64>），stream_chat/complete 统一吃它。
2. `build_body()` 纯函数按 reasoning_style 组装：
   - thinking_param：on→`"thinking":{"type":"enabled"}`，off→`"thinking":{"type":"disabled"}`；
   - effort_param：on→`"reasoning_effort":"medium"`，off→不发（o 系无可靠关闭参数，注明）；
   - enable_thinking_param：on→true，off→false；
   - thinking_budget_param：budget 有值才发；
   - 采样参数有值才发（不覆盖渠道默认）。
3. reasoning_counts_in_max_tokens=true 时记入 gateway.request 日志（截断排查用），不改语义。

## 任务 C：采样参数贯通（settings → server → agent → 前端）
1. settings Config/镜像/SettingsUpdate 增加 `temperature`/`top_p`/`thinking`/`thinking_budget`，
   全部可选；config_state_json 透出；前端设置面板加参数行（空=渠道默认）。
2. run_task 经 ChatParams 下传；前端 npm run build。

## 任务 D：角色映射 SUMMARY/TITLE/EMBEDDING（config.toml [roles]）
1. `[roles]`：`summary`/`title`/`embedding` = settings 配置名或 id；缺省回落主渠道。
2. server 按名字解析成完整渠道（base_url/model/key），解析结果记 gateway.request。
3. SUMMARY：滚动摘要走角色渠道（失败回落主渠道再失败降级占位符，现状不回退）。
4. TITLE：会话标题为机械截断时，任务结束用角色渠道生成 ≤20 字标题（失败保留原标题）；
   未配置 title 角色则维持现状不发起调用。
5. EMBEDDING：gateway.embed() 非流式 /embeddings 接口（记忆 v1 不消费，接口留好）。

## 任务 E：限流（config.toml [gateway] max_rpm）
1. `max_rpm`（默认 0=不限）：网关发请求前过本地节流器（最近请求间隔 ≥ 60/rpm 秒），
   全渠道共用一个节流器；日志记 gateway.throttle。

## 任务 F：降级链（config.toml [gateway] fallback_configs）
1. `fallback_configs = ["配置名", ...]`：主渠道当轮 stream_chat 失败（网络/429 穷尽/5xx/4xx）
   → 按序用降级配置重试同一步，每次切换发 Notice + JSONL gateway.fallback；
   全部失败才把最后一个错误抛出。取消标志置位立即停（不降级）。

## 验收标准（全过才算完）
1. cargo test 全绿：build_body 各样式单测（GLM 形态/Qwen 开关+预算/OpenAI effort/采样参数透传）、
   节流器间隔单测、降级链解析与顺序单测。
2. providers.json 加载旧格式（无新字段）不炸；13+5 家预设齐；/api/providers 带行为字段。
3. 真实渠道冒烟：采样参数/思考开关随请求体发出（logs JSONL gateway.request 可见）；
   摘要走 [roles] summary 渠道；主渠道断网时自动切 fallback 并发 Notice。
4. 前端设置面板可改采样/思考参数并即时生效；npm run build 成功。
5. 限流 max_rpm=30 时连续请求被按间隔排队。
