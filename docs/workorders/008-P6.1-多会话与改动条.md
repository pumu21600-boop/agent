# 施工单 008：P6.1 多会话与改动条（用户反馈修订）

## 背景
P6 交付后用户反馈三点：
1. 「新会话」不应清空历史——要 Codex 式「项目 → 会话列表」，新建对话与历史并存
2. 回滚不要放侧栏——要在对话流里显示「N 个文件已更改 +x -y ↩ 撤销」，直观看到改动量
3. 质疑 HANDOFF 文档的上下文成本（结论：HANDOFF 只在交接时读一次，git 记"做了什么"、
   HANDOFF 记"为什么/接下来"，组合收益更大；成本可忽略）

## 改动
- session：单文件 Store → SessionManager（`logs/sessions/<id>.json` 每会话一文件，
  标题取首条用户消息，列表按更新时间新→旧；id 白名单字符防路径穿越）
- recovery：新增 head_id / diff_stat（numstat 文件数+增删行）；
  **restore 重写**：只回退「基线..HEAD 之间发生变化的文件」（name-status 逐文件处理），
  不再整树 reset——修复真实事故：旧版 reset --hard 把用户已提交的文档也刷回了旧快照
- 核心循环：任务起点当场拍「任务起点」快照作基线（diff 只含本任务改动，不含历史漂移）；
  任务结束补「任务结束快照」提交后算 diff，发 Checkpoint 事件（SSE checkpoint）
- server：/api/chat 带 session_id（缺省自动新建，SSE 首事件回 session）；
  GET /api/sessions（项目名+列表）；GET/DELETE /api/session 带 ?id=
- 前端：侧栏「项目 📁 + 新建对话 + 会话列表（标题/相对时间/悬停删除）」；
  对话流内改动条（N 个文件已更改 +绿 -红 ↩撤销，confirm 后恢复）；拆掉侧栏检查点列表

## 验收
1. 三条会话并存，点选切换、新建不清空、删除单条不影响其余
2. 改 1 个已跟踪文件 → 条显示「1 个文件已更改 +2 −3」→ 撤销后文件回原样、
   未碰过的文件（含用户自己的改动）不受影响（单测 restore_only_touches_agent_changed_files）
3. cargo test 全绿（30 项）
