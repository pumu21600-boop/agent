## 二、件 1 验收标准（settings.rs 第一刀：tests 抽离）

1. `src/config/settings/tests.rs` 成立，内容 = 原 `#[cfg(test)] mod tests` 块整体（含全部既有测试：`backward_compat_legacy_json_deserialization` / `backward_compat_plugins_rename_migration` / `backward_compat_field_name_migration` 等），首行 `use super::*;`（如块内已有则不重复）；
2. `mod.rs` 对应位置替换为 `#[cfg(test)]\nmod tests;`，文件 1023 → 约 862 行；
3. 对外 API 零变化：`crate::config::settings::` 全部路径照旧（本刀不动物类型与迁移函数，零 re-export 需求）；
4. `cargo test` 全绿（256 + 5 集成，数量不减）、`cargo clippy` 零告警、`cargo build` 过；
5. 本地提交（不推送），消息写明「P2 件 1/7」。

## 三、后续每件验收标准（模板）

- 拆分前后 `cargo test` 通过数一致（搬移不改行为）；clippy 零告警；`cargo build` 过；
- 对外路径零变化（grep 实证：`crate::<该模块>::` 引用点数量与形态前后一致，mod.rs re-export 兜住）；
- 拆分行数对账：原子文件行数 = 各新文件行数之和 − 新增声明行（报告在提交消息里）；
- 每件一个本地提交；App.svelte 件额外要求真机冒烟（服务起、面板加载、聊天一轮）。

## 四、本单不做的事

- 不动 `App.svelte` 的内部逻辑（只搬移组件化，不改行为——拆分中发现的 bug 单独记，不顺手修）；
- 不在拆分里混入任何重命名/改名（改名是 P28/P1 的活，混拆会毁掉验收对账基线）；
- `browser/mod.rs` 未经完整盘点不动刀（本会话教训：控制台读中文必花，盘点必须走 node→文件→Read 通道）。
