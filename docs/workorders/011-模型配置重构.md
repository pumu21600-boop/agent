## 现状事实（自行核对，不构成指引）

- 配置数据在 `src/config/settings.rs`：`Settings` 顶层镜像字段（provider_id/base_url/
  model/models/context_length/max_output_tokens/temperature/top_p/thinking/thinking_style）
  与 `configs[]` 每项同名字段各存一份；两份之间的同步在 `sync_config_from_mirror()`
  （位置元组 snap.0…snap.9）与 `activate()`（逐字段手抄）。
- key 存储：`keys: BTreeMap<归一化base_url, DPAPI密文>`；`configs[].key_cipher` 为
  per-config 先例；文件里还带 v1/v2 旧格式迁移代码。
- 设置 API 在 `src/server.rs`：请求结构 `SettingsUpdate`（16 个全 Option 字段，按约定
  当 PATCH 用）；清除语义现为三种（`0` 清长度、`-1` 清采样、`""`/`auto` 清思考）；
  响应由 `config_state_json()` 手拼约 40 个键。
- 前端设置面板在 `web/src/App.svelte`（防抖自动保存、切配置前 flush）。
- providers.json 预设（18 家）与网关端点探测（`src/gateway/compat.rs`）的分工：
  配置层管存储与 UI，网关管请求组装——两者边界现状如此。
