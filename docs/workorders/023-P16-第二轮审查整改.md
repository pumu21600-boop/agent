## 交付

### A. 取消模型会话化（报告 D2，P0）

- `core/cancel.rs` 重写为**注册表 + 令牌**模型：`CancelFlag`（原子位，一个在跑任务一个）
  + `CancelRegistry`（`session_id → 当前这一轮的标志`）。旧全局标志的两个病根同时消失：
  ① 新会话开始不再 `clear()` 别人的标志；② 一次「停止」只停目标会话。
- `server.rs`：`AppState.cancel` 改为 `Arc<CancelRegistry>`；`chat()` 每轮 `begin(session_id)`
  拿本轮标志，并用 **RAII 守卫 `CancelRun`**（Drop 里按 `Arc::ptr_eq` 注销，不误删同一会话
  后来的一轮）——正常结束、提前 return、panic 三条路径都不留僵尸登记。
- 端点会话化：`POST /cancel?session=<id>` 停指定会话（不带 session = 停全部，命令行与内置页
  兼容语义）；`GET /api/cancel?session=<id>` 返回 `{cancelled, running}`，不带 session 返回
  `{cancelled, active}`。前端停止按钮带上 `currentSessionId`（切换会话在流式中被禁用，
  按钮目标恒为流式会话；id 未知的极早期退化为停全部）。
- 3 个单测：会话互不影响 / 新轮不复位别人且旧轮 end 不注销新轮 / 停全部与幂等。

### B. `edit_file` 局部修改工具（报告 1.2 头条 / 本轮 P1）

- 工具表新增 `edit_file{path, old_string, new_string, replace_all}`（danger_level 1，
  write_file 之后）：把文件中**唯一**出现的 `old_string` 精确替换为 `new_string`，
  改大文件不必重写全文（省 token，也避免重写时误伤其他内容）。
- 失败一律拒绝并把原因回喂模型（可自纠）：0 次命中 → 带「首行出现在第 N 行附近」定位提示；
  多次命中 → 提示加长上下文或 `replace_all=true`；空 `old_string` / 新旧相同 → 直接拒。
- **CRLF 容错**：文件是纯 CRLF 而行尾按 LF 书写（模型最常见形态）时，按 LF 规范化匹配 + 替换，
  再整体还原 CRLF（往返可逆才做，混合行尾不猜测）。
- 落盘走 `fsx::write_atomic`（与其他落盘点同一原子写）。
- `core/rules.rs`：`KNOWN_TOOLS` 登记（+1，登记表长度断言 8→9）；风险判定与 write_file 共用
  同一套「敏感文件 > 路径遍历 > 越界 > 常规」；`approval_scope` 按目录归类且**与 write_file
  分开记**（放行「改一处」不等于放行「整文件重写」）。三条审批档语义不变。
- 2 个单测（唯一替换/定位提示/不唯一/空串/新旧相同/越界/目录；CRLF 容错 + 行号回报）
  + rules 侧 1 个（路径与档位语义）。

### C. 日志多份归档（报告 E4）

- 轮转从「只留一份 `.1`」改为**多份倒位**：`.N` 丢弃，`.N-1`→`.N` … `.1`→`.2`，当前文件 → `.1`。
- 新增 `[logging].keep_archives`（默认 3，0 = 归档即删），`log.rotated` 事件带上 `keep`；
  `Logger::open / rotate_file / archive_current / shift_archives` 同步改造。
- 单测：`rotate_file` 原有 3 个更新 + **多份倒位丢最旧**、**keep=0 直接删** 两个新增。

### D. 扩展「覆盖内置」标记（报告新增面观察 1）

- `plugin/ui.rs`：`UiExt` 加 `shadowed`——工作区扩展同名顶掉内置时为 true。
- 前端扩展面板徽章：`内置` / `工作区` / **`工作区 · 覆盖内置`**（悬停说明），
  避免把「项目自带的那份」误当内置扩展。
- 单测：两个根目录各放同名扩展 + 工作区独有一份，断言只留一份且标记只在覆盖时置位。

## 顺手修（本轮真机暴露）

- **沙箱探针标记文件重名竞态**：`probe_workspace_read` 的标记名写死 `.agent_probe_read.txt`，
  并发自检（测试并行 / 界面连点两次）时两个探针互相删标记 → 偶发「file not found」假失败
  （全量测试时真机撞到一次）。改为带进程号 + 自增序号的唯一名。
- **mock 渠道剧本触发条件**：旧逻辑「带 tools 参数就吐工具调用」会把**任何**普通消息都卷进
  工具循环，慢流 / 纯流式冒烟全测不到（本轮真机踩到：慢流请求 84ms 就跑完，取消测试假过）。
  改为显式触发（「读 …」/「编辑 …」/「死循环」），并新增「慢流」长流剧本（30 片 × 300ms，
  供中途取消验证）。
