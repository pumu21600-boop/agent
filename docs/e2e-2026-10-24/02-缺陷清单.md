## D0【严重·功能·已修】`rpReviewBaseline` 未声明（丢 let），炸断产物面板与工作区切换

- 现象 1：产物面板永久卡「加载中…」（多次采样、跨分钟不复原）。
- 现象 2：每次切换工作区/项目，弹假错误「切换项目失败: rpReviewBaseline is not defined」（实际切换已成功），且 git/产物面板不重置重拉——正是 2026-10-13 修过的「改动串到另一工作区」症状复发。
- 现象 3：面板操作期间反复触发未捕获 ReferenceError（控制台噪音）。
- 根因：`web/src/App.svelte` 三处赋值无一声明（P2 拆分丢 `let rpReviewBaseline`）：
  - 行 463（切工作区函数内，重置块）→ 打断其后 `loadReview()/loadArtifacts()` 调用，且被外层 catch 捕获弹假错误；
  - 行 1896（`loadArtifacts()` 内，基线存在路径）→ 函数在此中断，`rpLoading` 永远 true → 产物面板卡加载；
  - 行 3271（openSession 路径）同类中断。
- 修复：补一行 `let rpReviewBaseline = '';` 即可（或删掉这个已无模板引用的死变量——它没有任何读取方，三处赋值可整体删除）。
- 复现：100%。切到有检查点的会话 → 开产物面板 → 永远「加载中」；或任意切换一次工作区 → 假错误弹窗。
- 附注：Svelte 严格模式下对未声明变量赋值即 ReferenceError；且 463 行所在 try 的 catch 原本是死代码改造成的弹窗（注释自述），恰好把真错误以假消息（「切换项目失败」）暴露出来。

## D1【严重·环境】火绒安全静默拦截新构建 exe 的外网连接，应用报「网络层不通」

- 现象：服务网关对一切外网渠道 TCP 连接超时（每次精确 15s connect_timeout）；同机 curl / Node / PowerShell 对相同目标全部秒通；环回地址正常。
- 根因链（已实证）：
  1. 干净环境重启服务 → 仍失败（排除进程环境变量污染）；
  2. 独立最小 reqwest 探针（reqwest 0.12.28，与本应用同栈）从干净 shell 跑 → 对 baidu/sensenova/stepfun 全部 TCP 超时，环回 200 OK（排除本应用代码/构建回归）；
  3. Windows 防火墙出站策略 AllowOutbound、无按程序拦截规则（排除系统防火墙）；
  4. 机器装有火绒安全（HipsDaemon.exe / HipsTray.exe 常驻）→ 未签名的新编译 exe（target/release/pawch-agent.exe、探针 reqprobe.exe）出站被静默丢弃；签名知名程序（curl/node/powershell）放行；
  5. 历史对照：10-21/10-22 服务直连 stepfun/sensenova 全部成功（当日构建被放行过）；10-24 11:31 重新构建后新哈希即被拦 → 每次重新构建都会复发。
- 影响：用户每次重新构建 Pawch Agent 后，所有外网渠道静默失效，报错文案是「检查 Clash/系统代理或本机网络」——方向碰巧对了一半（开代理可绕），但真实原因是火绒按哈希拦新 exe。
- 修复建议（给用户拍板）：
  a. 火绒里把 `target\release\pawch-agent.exe`（或整个仓库目录/开发目录）加入信任区 —— 一次性解决；
  b. 应用侧可在错误文案里补充「若刚重新构建过程序，检查安全软件是否拦截」；
  c. 长期：发布构建签名。
- 当前测试环境的临时绕行（本次 E2E 已采用）：开启系统代理（ProxyEnable=1，指向 Clash 127.0.0.1:7897）→ 网关连接走环回（火绒放行环回）→ Clash 出网。**收尾时把 ProxyEnable 还原为 0**（发现时的原始状态）。
- 顺带验证（正向结论）：网关「网络层失败→重建客户端重读系统代理→重试」的 Clash 开关热恢复设计真实有效（开代理后下一次请求即恢复，无需重启服务）。

## D2【一般】归档当前激活会话后：侧栏无激活项，但消息仍写入该归档会话

- 步骤：新会话 → 会话菜单「归档会话」→ 归档的是当前激活会话。
- 实际：侧栏 `.conv.active` 消失（无任何激活项），顶栏标题残留「E2E测试会话（分叉）」，输入框可用；此时发消息，服务端 `/api/session` 仍指向该归档会话，消息成功写入归档会话（已实测：2 条消息写入，归档会话 updated_at 更新）。
- 预期：归档当前会话时应自动切到相邻会话或新建空会话；或明确提示当前会话已归档、停止输入。
- 复现：100%（归档当前激活会话即触发）。

- 步骤：重命名弹窗清空标题 → 点「确定」。

## D4【一般】markdown 表格不渲染

- 现象：模型回复标准 GFM 表格（`| 列 | 列 |` + `| --- |` 分隔行）时，渲染为普通段落+换行，管道符原样显示；标题降为 h4（设计内）、代码块正常。
- 根因：`web/src/lib/md.js`（69 行自研渲染器）只实现标题/列表/代码块/引用/分割线，无表格支持。
- 修复建议：md.js 增加 GFM 表格块解析（连续行以 | 开头 + 第二行 |---| 判定）。
- 复现：让模型回 markdown 表格即可（本测试已复现）。

## D7【翻案·非缺陷】定时任务行内「删除」按钮（原疑似失效）

- 复盘结论：**删除功能正常**。第一轮报「点击无反应」是测试脚本缺陷——探测确认弹窗时用 `offsetParent` 过滤可见元素，而弹窗层 `.modal-backdrop` 是 `position:fixed`（offsetParent 恒为 null），被误判为「没弹窗」。
- 桌面壳 CDP 复测：点「删除」→ 确认弹窗（fixed/1280x860/可见）→「确定」→「已删除」→ 列表移除 → API 清零，全链路通过。
- 经验沉淀：探测 fixed 定位的浮层要用 getBoundingClientRect/visibility，不能 offsetParent。

## D8【建议】若干观察项（不计失败，未动）

- 定时任务跑出的会话标题 = 原始提示词截断（含【项目现状】注入块），不像手动会话有自动起名（「数字序列」等）——观感差，建议定时会话复用任务名或走标题摘要。

- 新实例（无 localStorage）首次开右面板时主体全空白，无引导（有「+」可加标签，可接受但可更友好）。
