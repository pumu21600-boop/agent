1. **本机 GNU 工具链损坏**：dlltool CreateProcess 失败，项目已用 `rust-toolchain.toml` 钉死 MSVC（本机有 VS 2022 Community），不要改回 gnu。

4. **商汤中转 401 code 16 Forbidden** = key 无效；key 走 DPAPI，页面显示尾 4 位（key_hint）供自查，完整 key 永不出内存/日志。

9. **SeChangeNotifyPrivilege 剥不掉**：`CreateRestrictedToken(DISABLE_MAX_PRIVILEGE)` 只把特权置禁用不删名字，且系统固定保留 SeChangeNotifyPrivilege（遍历绕过，无害）；探针按名字白名单断言，别用 whoami 输出数个数。

16. **体积星云的坑**（P14 三轮返工，改 `web/src/galaxy/` 前必读）：
    - **sampler 必须写精度**：GLSL ES 3.0 里 `sampler3D`/`sampler2D` 没有默认精度，写成 `uniform highp sampler3D uNoise;`，否则编译报 "No precision specified"（会被前端兜底逻辑吞成"WebGL2 不可用"，看状态条才能发现）。
    - **步长要按场景尺度归一**：体积积分里 `dt` 直接用世界单位时，密度系数会随场景半径数量级失控（一次调参就把整团云曝成白球）；统一用 `dt/uRadius`。
    - **颜色必须分属不同结构**：把互补色当作同一团丝的"变色"（丝脊换补色）= 青与品红沿视线积累 → 混成灰白（同色实验证明着色链路没问题）。参考图的青气/橙尘/品红核是**三套独立的 ridged 场**，各自取样、各自配色、尘埃还负责吸光。
    - **包络要强**：团簇包络弱了（exp 系数 1.4）一条视线会穿多团，颜色沿途平均成灰褐；系数 2.1 以上保证一线 1-2 团。
    - **体渲染锐度有物理上限**：44 步积分的步长 ≈ 64³ 纹理最细特征，丝永远偏糊；解法是**合成通道里叠屏幕空间细丝**（2D ridged fbm + 低频域扭曲拉流向 + 染色跟随底色 + 以视线方向/uZoom 锚定），照片感来自后期而非无限加密体积采样。
    - **烘焙基函数进纹理**：把 R/G/B/A 四通道做成 4 种基（fbm/脊络/中频折痕/高频毛刺）而不是 4 个八度的同种噪声——abs 折痕是 V 形锐利的，一次采样同时拿到四种结构素材。
    - **尘埃的配比决定观感**：尘埃发光调低 + 消光调高 = 暗剪影，青气才压得住场；配反了就是一滩黄泥。
    - **PS 修改文件用 `[IO.File]::ReadAllText/WriteAllText` + 显式 UTF8**：`Get-Content|Set-Content` 默认走系统 ANSI（GBK），UTF-8 中文会被读成乱码再写坏（Galaxy.svelte 曾整文件报废重写）。
    - **恒星"看不见"先查 `gl_PointSize` 尺寸公式**（`aSize*(H/2/tanFov)/z`，与相机 z 同阶），不是没画——调试：临时把尺寸乘大系数。
    - **布局半径别线性累加**：单会话小项目会把后续团线性推远、星云散成孤岛；用 `max(累加, 460*√i)` 次线性增长。
    - **调参只能小步走（P14 五轮教训）**：尘埃发光/消光与空腔掩膜频率一次动两个档位以上，就从"参考图"翻到"海绵/黄泥"（第四轮橙尘 emission 1.45→2.6 + 消光 5.2→3.0 + 空腔频率 0.40→0.30 三处一起动，全画面翻车）；一轮只动一组参数，截图对比再走。
    - **团状大理石纹的解法是流向拉伸 + 空腔掩膜**：ridged 场 + 强域形变会出闭合漩涡（玛瑙/指纹感）；把采样域沿低频方向场各向异性压扁（沿流向 0.40、垂直 2.0）丝缕变细长烟帘，低频 fbm 掩膜（freq≈0.38，留 10% 底）打破满球剪影、出非对称瓣和大暗腔。
    - **恒星"刺眼"的根源是 sprite 基础尺寸 + 白晕**（P14 六轮：会话星 95+32·size 的基础尺寸让每颗星糊成 130-240px 白球）：会话星压到 20+8·size、glow 0.60→0.34、halo 0.26→0.10、外晕纯 vColor 不掺白——恒星只是锐利小光点，大面积泛光的是云。
    - **品红核要"颗粒结"不要"平滑光球"**：半径收到 0.58σ、高频毛刺(A)通道打颗粒（grain 0.30+0.70·smoothstep(s.a)）、白热只留极中心（hot mix ≤0.32），否则中心又是一块奶油饼。
    - **宽橙帘要用"青气互补门控"**：单靠折痕线(B)只有细线；补一层低频折痕场大块高值区当宽帘，但必须乘 (1-smoothstep(0.25,0.60,s.g)) 让橙只长在气的间隙——没有门控就是全画面橙斑（发霉感）。
    - **照片感的最后一层是分级**：只对蓝主导像素做冷色深化（isBlue 门控 ×vec3(0.86,0.96,1.16)），暗腔底给深蓝余光而不是纯黑，亮脊顶 mix 白热——整体蓝调才对得上参考图。
    - **云中视角（相机 0.45×sceneRadius）三条铁律**（P14 七轮）：① 屏幕空间的"大尺度暗腔"在云内视角会变成满屏豹纹（形状恒定、与视差无关，一眼假）——降到 0.55 底的轻微暗示，暗部交给体积层的暗尘带；② 特征被放大 ~2 倍，噪声采样频率同比抬高（1.7→2.4）；③ 长路径积累会把中等噪声值糊成"棉花底"——smoothstep(0.46,0.94) 掐掉全部中值只留脊尖，脊间压黑。
    - **暗尘带用低频脊络反向做，不用阈值化 fbm**：fbm 阈值出孤立圆斑（迷彩），脊络天然连片沿折痕走向（lane = G@0.45freq，env ×= 1-0.78·smoothstep(0.55,0.90,lane)）——参考图的暗部是连成片的尘墙。
    - **高频域形变 = 揉皱锡纸**：两级 warp 强度（0.9/0.5）会把脊络场闭成小环，满屏"褶皱纸"（用户：更奇怪了）；压到 0.55/0.30 只留大尺度卷曲，配流向拉伸出长弧丝缕。屏幕空间的丝纹 mask 也必须跟亮度走（smoothstep(0.10,0.35,lum)），在暗区刷丝会把黑底抹成均匀中灰。
    - **"纹理感太强"的总解 = 柔雾层 + 大形态（P14 八轮）**：全部锐化丝线 = 雕刻版画，没有"星云飘散"感。气体必须分两层——柔雾体（fbm 低频、无锐化、占主导）+ 丝缕（嵌在雾里、跟随暗尘带分布 fil×(0.3+0.7·smoothstep(0.40,0.78,lane))）；采样频率宁小勿大（1.15，大形态占画面 1/5~1/3，细节只是次级调制）。多轮拉锯结论：结构"太锐/太密"永远比"太柔/太大"更难看，往柔里调不会错。
    - **"为什么非要弄那些线"（P14 八轮用户原话，终审结论）**：所有"线"都来自同一条流水线——ridged 噪声（数学本质 = 沿噪声极大值描等高线）+ 阈值/pow 锐化 → 只剩线活着；体积里如此，屏幕空间刻丝也如此，全删。**自然云雾的正确配方**：`field = fbm低频·0.82 + 脊络·0.12 - 高频毛刺·0.20`（减高频 = 侵蚀边缘啃出絮状），`body = env · smoothstep(0.18,0.58,field)`（smoothstep 带出"形"，边缘是渐变带不是线），体色随亮度渐变（深蓝→青→白）。两个极端都翻过车：全描线（用户否）、纯 fbm 无带（失焦光斑）；渲染分辨率下限 0.42（0.3 再放大本身就"失焦"）。
    - **P14 终版架构 = 离线烘焙（借鉴 wwwtyro/space-3d，Unlicense）**：用户终拍板"不要纹理"。每帧光线步进的细节密度有物理上限，改为打开视图时把星云一次性烘进 3×2 cubemap 图集（位移迭代噪声 = 6 步域位移 + 经典 4D Perlin，多层颜色/尺度/强度/衰减 alpha 叠加），运行时视线与巨壳（6×sceneRadius）求交采样——每帧成本从 44 步积分降到 1 次纹理采样。团辉光在采样时按团方向叠同色高斯（星云与数据仍对应）。烘焙要点：① `gl_FragCoord` 是窗口坐标不是视口坐标，图集分面必须传视口原点校正（否则 2~6 号面采错区域、面间硬缝）；② 位移迭代噪声输出集中在 0.5 附近（方差小），intensity 1.5~1.9 放大 + falloff 4~20 切云块；③ scale 决定形态占比（~1.0 = 一块云约 1/5 天球，0.3 = 半球一块 → 必糊）；④ **分层顺序即合成顺序：蓝气 → 橙纱（高衰减只留亮块）→ 暗尘带压轴**——压轴暗层在蓝、橙上都刻近黑暗带；没有压轴暗层，蓝+橙覆盖并集填满整屏（无黑场=不像照片）；⑤ 默认相机方位对着烘焙完成后的"蓝气主体"方向选（az 3.6）；⑥ **壳半径必须动态跟随相机**：`radius = max(6×sceneRadius, |camPos|×1.6)`（P14 十轮用户实拍"最外围有个球"）——平移上限是按轴算的，斜向 2.5×√3 ≈ 4.3×，再加拉远 4.5×，组合位置必然超过任何静态壳；相机一出壳，星空里就悬着一颗贴图球（截图实锤）。动态壳让相机在几何上永远在壳内，且壳变大不改变采样方向分布（方向场连续无跳变）。
⑦ 深蓝底层 falloff 别低于 ~4.5：覆盖满球没有黑场 = 同样读成行星表面；⑧ **合成通道的圆形暗角必须删**：星云铺满画面后"中间亮四周黑"的圆形渐晕 = 整个屏幕读成一颗球（P14 九轮用户："还是个球"），参考照片没有暗角、星到边；⑨ 单层大圆橙团同理读成行星：橙层 scale ≥2.3 + falloff ≥19 打成小碎块；⑩ **团辉光必须压到若隐若现**（falloff ≥40、强度 ≤0.12）：最大项目团的辉光在暗背景上就是一颗巨大的青色圆盘（P14 十轮用户实拍"圆形画面"）——任何"径向渐变光斑"在暗背景上都会被读成球；⑪ **平移限幅必须向量限长 + 密度滑条保住暗尘带**（P14 十一轮用户："往上下左右还有一堆没光点的星云空间"）：平移按轴限幅时斜向组合跑出星场（2.5×√3 ≈ 4.3 倍），云外全是无星区——改为目标向量限长 0.45×fieldR（fieldR=buildScene 返回的光点散布半径）；拉远上限单独定 2.8×fieldR（缩到最小要一眼看全所有光点，见 ⑫）；密度滑条调低时暗尘带层保底 max(0.72, density)——黑场是构图的一半，不能跟着密度一起消失。**测试必须覆盖平移到上下左右限幅的状态，不能只测默认视角**；⑫ **拉远上限 = 2.8×fieldR，不是"越近越好"**（P14 十二轮）：用户否了 0.85×——缩到最小必须一眼看全所有光点。经验公式：拉远上限 ≈ 星场半径 / tan(垂直半视角) ≈ fieldR/0.445 ≈ 2.25×fieldR，取 2.8×fieldR 留余量；"有云无星空区"由平移限幅负责（拉远看向星场中心，不产生空区），两个限幅各管一件事，别混。

21. **localStorage 恢复的页签 ≠ 已加载的数据**（2026-09-24 用户报「用量面板显示插件未加载，切走再回来才好」）：`rpTab`（右侧面板停在哪个页签）存 localStorage、`extCurrent`（当前是哪个插件）只在内存——开机时 `/api/ext` 清单还没回来，右侧面板已照着 `ext:usage` 渲染，`extCurrent` 还是 null → 显示「插件未加载」，必须切到别的页签再点回来（`openDockPlugin` 才补 `extCurrent`）。**同一个坑还埋在设置分区**：`settingsTab` 也持久化，而技能/MCP/插件分区的数据原先只在 `pickSettingsTab` 的点击里拉，上次停在「技能」再开机，打开设置看到的是空列表。**纪律**：① 凡是从 localStorage 恢复的「选中项」，都要有一条响应式语句把对应数据补齐（照记忆分区的 `$: if (settingsOpen && settingsTab === 'memory') loadMemory();` 写），别只挂在点击处理函数上；② 选中项指向的东西没了（插件停用/删除）要主动退回默认项，别把用户留在死页签上；③ 清单还没回来时占位文案说「加载中…」，别用「未加载」这种结论性措辞（会骗人）。
22. **无头会话（P22-A）三条**：① **`status` 与 `error` 必须一致**——调用方（CLI/定时/子代理）按 status 判退出码，`done + error` 会让失败被当成功（第一版就踩了：run_task 返 Err 只记 error 没改 status）。纪律：出错分支同时置 status=error，组装结果处再兜底「有 error 就不是 done」。② **无头接口整轮结束才返回**，运行中拿不到 session_id——测「会话在跑 → 409」必须**自带固定 session_id** 发首请求（等响应再取 id 时首轮早结束了）；自带 id 也复现了真实用法（定时任务/子代理都按预设 id 唤醒）。③ **取消守卫要随任务生命周期**：超时用 `tokio::time::timeout` 包 JoinHandle（drop JoinHandle 只是分离、不 abort），守卫放进 spawned 任务里——超时后任务在后台收尾也保持「会话在跑」登记，不会出现双写会话文件；反之把守卫留在地控件里就会出现「登记已注销、任务还在跑」的窗口。
23. **模块级 `Mutex` 静态的自锁死（P22-C 真机踩到，测试直接挂死）**：本项目大量用 `OnceLock<Mutex<…>>` 模块静态（LEDGER / PINNED / NOTICES / RUNNING / DEPTH / TOKENS…），配套访问函数（`depth_of` / `running_for` / `subagent_tokens`）自己也要锁同一把锁——**持锁期间调访问函数 = 再锁一次非重入 std Mutex = 当前线程永久自锁**（现象：cargo test 某个用例挂住不返回，不是慢，是死）。纪律：① 先算值再上锁（`let d = depth_of(p) + 1; slot.lock()…insert(d)`）；② 新增这类静态时，访问函数与写入点尽量靠近定义，一眼可见锁关系；③ 跨用例共享的静态，测试里先 clear 再断言（本文件测试已互相踩过）。
24. **mock 渠道剧本两个坑（P22-C 踩）**：① `emitToolCall` 内部会 `res.end()`——一轮要发多个工具调用不能用它，必须手写帧（tool_calls index 各自递增）最后统一 finish_reason + DONE + end，否则 write-after-end 直接把 mock 服务打崩（Node 进程退出，后续请求全变 502）；② 慢循环剧本的路径交替基准必须用**请求内**状态（tool 消息数），用全局计数器会被父子多个并发请求互相踩错拍——子代理被核心循环的「重复工具调用」检测误杀；且交替目标要与当前路径去重（路径本身就是它时照样连续重复）。
25. **「失败重试」不是死循环 + 工具错误必须人话化（2026-09-25 用户反馈）**：用户截图——browser navigate 超时（`[backend_unavailable] 浏览器会话异常已重置：CDP 调用超时: Page.navigate`）后模型重试同一调用，被「连续两步相同工具调用」护栏当场判死循环终止，用户看到的是天书错误红横幅，而不是 AI 说「访问超时」。两条修复：① 护栏加例外（`is_repeat_loop` 纯函数）：两步签名相同但上一轮**全部失败**时重试放行——失败本身就是「状态可能已变」的信号，真正要防的是对成功调用的重复请求，失败重试由步数上限（16）兜底；② 浏览器后端类错误人话化（`friendly_backend_error`）：超时→「访问超时：浏览器没有在预期时间内响应…可以重试一次；仍不行就 close_browser 后重新打开」，断开→「浏览器连接已断开…重试 navigate 会自动重新拉起」，人话在前（模型转述给用户）、原始细节留尾部（诊断用）、错误码仍由 Display 前置。**纪律**：工具执行失败的回喂文本是给模型转述的，不是给用户看的天书——凡工具错误，先想「模型拿到这句能不能自然地说人话」。
26. **排队消息的双重所有权会变成请求风暴（2026-09-27 用户实锤，10 秒 2000 条）**：用户场景——网络抖动把首轮任务的 SSE 连接弄断（快照抓到 chrome-error 页「连接已中断/检测到网络更改」），**前端以为会话空闲了、服务端其实还在跑**；用户再发一条 → 服务端走排队快速路径（立即返回 queued）→ 前端把它记入 outbox → 流结束 → finally 的出队逻辑把**同一条**再 deliver → 又排队 → 又出队……每秒约 190 次，10 秒灌了 2000 条进服务端队列；首轮的 60 字回答流进了死连接用户永远看不到，巨量排队被一次性排进后续轮又撞渠道 429。**双重所有权是病根**：027 的前端 outbox（本页看得见忙→本地排队）与服务端 steer 队列（本页以为空闲→POST 被排队）都能「接管」同一条消息的投递，出队逻辑却假设「deliver 返回 = 消息已被本轮消费」。修复三条：① 前端 d.queued 分支把消息从 outbox **摘除**（服务端接管，前端绝不重发）；② `reconcileServerQueued` 对账轮询：2s 查 `/api/cancel?session=`，服务端空闲后从会话文件重载消息（被死连接吞掉的回答全部找回；会话不在当前页就丢本地缓冲、下次打开重建）；③ 服务端防线：单会话排队 ≥32 条即 429 人话拒绝（`chat.queue_full` 审计）——正常永远到不了，到顶即客户端在循环重发。**纪律**：任何「消息交给别处投递」的路径，本地队列必须同步摘除；SSE 流断 ≠ 任务结束（服务端还在跑），恢复事实的唯一来源是服务端会话文件。
27. **「浏览器打不开某网站」先查系统代理开关，别急着改程序（2026-09-27 实锤）**：用户报面板浏览器打不开谷歌且任务卡住。排查链：① 面板错误页 `ERR_CONNECTION_TIMED_OUT` = 直连被墙站点的典型死法；② `curl --noproxy '*' https://www.google.com` 直连超时、`curl -x http://127.0.0.1:7897` 秒通——代理客户端活着且能通；③ **注册表 `ProxyEnable=0`**——代理客户端把「系统代理」开关关了（切 TUN/开关被拨掉），浏览器（WebView2/Edge 跟随系统代理解析）直连死。整壳重启无效（环境是新的、开关还是关的）——**这不是程序 bug**。（事后确认：用户是故意关代理测失败路径的输出。）程序侧该做的已做：navigate 落到 chrome-error 时（成功与超时两条路都查，`Page.getNavigationHistory` 取当前 URL）给模型「访问失败 + 不要再重试导航 + 系统代理诊断」的人话（`chrome_error_note` + `system_proxy_hint`：读 HKCU 注册表 ProxyEnable/ProxyServer，开关关着但本地代理端口活着就点名「打开系统代理或 TUN」；开关开着仍不通则提示查分流规则）；CDP 超时路径（错误页未落地、tab 的 CDP 可能楔死拿不到 URL）由 friendly 文案直接带 `system_proxy_hint`。**失败耗时长的一半也是程序问题**：`call_and_wait_event` 里调用超时（20s）后还会再干等事件 22s——而无论事件来没来最终都返回调用错误，那段等待 100% 纯浪费（一次注定失败的导航干耗 47s）；已改为调用失败立即返回，47s → 21s（剩余是 Chromium 自身的连接放弃时间，不可压缩）。**诊断纪律**：网络类问题先做三条对照（直连/显式走代理/查 ProxyEnable），一分钟定位是网络、代理客户端还是程序。
28. **Windows 测试 mock 的两个 socket 坑（2026-09-27 gateway 测试踩）**：① 非阻塞 listener 上 `accept()` 出来的 socket **继承非阻塞标志**（Windows 行为），`write_all` 撞 WouldBlock——被 `let _ =` 吞掉后连接空手关闭，客户端只看到 `error sending request`；接受后必须 `set_nonblocking(false)` 再写。② 不读请求就写响应再关闭：客户端未发的请求字节留在本端接收缓冲，Windows 对「有未读入站数据的关闭」直接回 **RST（os error 10054）**，客户端拿到的是「连接被重置」而不是写好的响应——先阻塞 read 一次把请求读掉，再写响应。另：测试探针里的临时 `TcpStream` 别用命名绑定攥着不放手——对端阻塞 read 会等一个永远不来的字节，测试直接挂死（这条自己踩了自己）。gateway 的 `client_rebuild` 测试已改为本地 mock（回 401），不再依赖外网与系统代理状态。
29. **确诊即终局 + 引导消息要追上最终回答（2026-09-27 用户反馈两条）**：① navigate 超时错误文案把「可以重试一次；仍不行就 close_browser 后重新打开」放前头、系统代理诊断缀尾——模型照前半句连做 close_browser + 再导航，又烧一分多钟；而「代理客户端活着 + 系统代理开关关闭」是**环境误配**，重试/重开 100% 无解，确诊后必须改给终局文案（不要再重试、重开也救不了、直接结束向用户解释怎么拨开关；`probe_system_proxy` 结构化探测 + `timeout_error_text`/`chrome_error_text` 纯函数可单测）。**同一轮还暴露了错误页漏检**：chrome 错误页的 `Page.getNavigationHistory` 仍记**原目标 URL**，只有页面自报的 `location.href` 才是 `chrome-error://`——旧 `current_page_url` 只看导航历史，落点检查永远探空，错误页快照被当 ok:true 返回（用户看到的「可以点刷新验证」就是这么来的）；已改为 location.href 优先、求值不可用回退历史（进程内 mock CDP WS 单测覆盖两路）。**纪律**：给模型的处置指令不许自相矛盾——诊断说「环境问题」就不要在同一句里留「可以重试」；文案是纯函数、探测是副作用，分开才可测。② 「立即发送（引导）」在模型**流式输出最终回答期间**到达时错过全部决策点（决策点只在每步模型调用之前），旧逻辑按最终回答直接收尾，引导被服务层收尾 `drain_all` 捡去当 followup 另起一轮——用户看到自己没再说话却多出一轮「好的，已结束」。修复：最终回答落地后再 `take_steering` 一次，有引导就并进本轮继续（已流出的回答不丢、不另起回答气泡；steer.rs 文档同步两个取走点）。前端 `d.turn` 去重把已引导气泡也算上（收尾竞态残留时不再补重复气泡）。**纪律**：「只在 X 点取」的队列，收尾动作（title 生成、loop.finish、done）之前必须再取一次——流的尾部就是最容易漏的窗口。真模型全流程验证欠账（引导在回答中途到达的场景），待用户下一轮真机使用确认。
30. **布局耦合的合理性门槛会把 webview 冻死在旧矩形上（2026-09-27 用户截图实锤）**：壳模式网页面板的 webview「盖进聊天列、顶在工具栏下 35px、又宽又矮」。测量链（截图 150% DPI 逐像素 + 壳日志 rect 指令对照）：壳最后一次收到的矩形是旧布局下的 `935,125 748x655`，实测 webview 位置与它严丝合缝（x935×1.5=1403 ✓ 宽 748×1.5=1122 ✓）——**冻结在旧矩形**；而面板真实内容区是 (≈1033,≈90)。根因：web-tabbar 行是 `{#if webTabs.length}` 条件渲染，浏览器会话一关（无标签页）整行消失、内容顶从 125 掉到 ~90；而 `panel_viewport` 的合理性门槛写死 `y>=100`（按「标签条常在」的旧布局推的 44+44+39），把之后**所有正确矩形**（含拖分隔线后的）当「量早了」拒收，连 webview 从此再也不会被摆正。门槛想挡的「量早了」瞬态（y≈91）其实是同一件事——状态未加载时标签条还没渲染——y 值根本分不出「瞬态」和「无标签条的正常布局」。修复三层：① 门槛只挡真垃圾（x/y<0、w/h 过小），不再按布局猜 y；② 前端加**就绪门**：`loadWebState` 到手前不量矩形（瞬态从源头消失），就绪后补一发同步（标签条增删若没引起 web-body 尺寸变化，ResizeObserver 不开火，这一发是唯一机会）；服务端 `skipped` 时前端清 key 等重试（旧代码把拒收当成功、坏矩形被标记「已应用」）；③ **孤儿 webview**：服务重启不关壳里的 child webview，reset 只在下次建会话时才发——重启后一条旧页面悬在错误位置无人管。改为壳接入控制通道时若本进程**还没有浏览器会话**就立即 reset（会话活着时不清：只是通道闪断，webview 还归当前会话管）。**纪律**：①「合理性检查」写死具体布局数字 = 布局一变就变成永久性拒收——门槛只能挡物理上不可能的值；② 条件渲染的行会让「量早了」和「合法新布局」在数值上不可分，瞬态要在产生端（前端就绪门）挡，不要在消费端猜；③ 逐像素对照壳日志与截图（rect×DPI=屏上位置）是定位这类「冻结在旧矩形」问题的直通车。
31. **三条用户反馈同日（2026-09-27）：引导被审批卡死、面板宽度又不同步、切界面丢对话**：① **引导 vs 审批**：用户「立即发送」后引导 120 秒无反应——日志还原：引导到达时模型已开始生成下一步（错过决策点），该步的 browser fill 弹了审批，审批默认等 120s 超时自动拒，引导在超时后才被取走。「引导=改方向」的语义必须贯穿所有等待点：审批的 select 加引导臂（`SteerQueue::has_immediate` 非消费探针，100ms 轮询），有立即引导即按拒绝放行挂起操作——引导消息本身留在队列给决策点，模型拿着「已取消+新指令」秒级重规划。另修前端：引导请求**不登记 streams**（旧行为顶掉运行中轮次的流条目、finally 又误删，本页从此以为会话空闲）。已知欠账：非审批的工具执行期（浏览器超时 ~30s）引导仍要等工具返回——真中断需要工具级取消，留口。② **就绪门第二入口**：面板有两条状态刷新路（loadWebState + 2s agent 轮询），agent 自动唤起面板走的是轮询路——就绪标志只在 loadWebState 置位的话，自动唤起场景下视口同步被永久挡死（「拖宽度 webview 不动」是我上一条修复引入的回归）。纪律：**给一条数据通路加门，先穷举它的全部入口**。就绪置位放在标签清单更新之后（补发的那一发要量到定型几何）。③ **对话内容丢失**：切工作区清缓冲**不清流登记**——切回来 loadSession 走「本地缓冲」分支拿到被清空的缓冲，历史全不见；重开程序/切走再回来时服务端可能还有一轮在跑，本页拿到的是旧文件且无人补。修复：切工作区 abort 全部流并清登记；deliver 的 finally 不复活已清缓冲的条目（空数组是 truthy，会骗过「本地缓冲」判断）；loadSession 打开会话时查 `/api/cancel` 的 running，在跑就挂 `reconcileServerQueued` 对账（服务端空闲后从文件重载，缺的尾巴自动回来）。**纪律**：前端「缓冲优先于文件」的快路径，必须先确认缓冲的完整性来源（本页流）还成立；服务端还有活儿的会话，打开时永远要挂对账。
