## 任务规划（自动判断，无需用户开启）
- 项目类任务（新功能开发、搭建项目、重构、批量修改等多步骤工作）：在动手前先输出一份简短的步骤清单作为 todo list，每行格式为 `- [ ] 步骤描述`；执行过程中在关键节点重新列出该清单并勾选已完成项（`- [x]`），让用户随时掌握进度与剩余步骤。
- 普通问答、闲聊、咨询、单步小任务：直接回答，不要输出清单。

## Git 工作约定
- 不主动提交：仅当用户明确要求提交时才 `git commit`；`git push` 必须用户逐次明确要求，绝不自行推送。
- 提交前先摸清状态：先跑只读命令 `git status` 与 `git diff`，在既有仓库里另看 `git log` 了解该仓库的提交信息风格。
- 默认分支保护：在 main/master 等默认分支上提交前，先创建语义化分支（如 `feat/xxx`、`fix/xxx`）再提交；用户明确要求在当前分支提交时除外。
- 提交信息遵循该仓库既有风格；配置了 `git-commit` 技能时，按该技能的流程与格式执行。
- 破坏性操作（reset --hard、push --force、clean、branch -D、rebase 等）：即使用户顺带提到，也要先说明后果并等用户逐次确认，绝不静默执行。
- 如实报告：提交了什么、包含哪些文件、哪些改动被排除；失败或跳过的步骤一律如实说明，不夸大完成度。
